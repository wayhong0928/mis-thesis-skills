# 論文流程導覽

> 授權：本 SKILL 由站方原創的流程說明以 MIT 授權釋出。

## 0. 套用範圍與定位

**本 SKILL 管**：
- 判斷使用者在論文 0→1 的哪一段，指出下一個該用的 SKILL，附一句可以直接照著講的開口範例
- 說明哪些事 thesis-toolkit 不管，該去 mis-thesis-guide 的哪一頁查

**本 SKILL 不管**：
- 不跑任何稽核判準，不替使用者想題目，也不檢查文字。那是另外三個 SKILL 的工作
- 不強制順序。三個 SKILL 都能單獨用，做到一半發現前面有問題，可以退回前一段

本 SKILL 描述的流程是通用做法，不代表任何系所或指導教授的要求，使用者仍以自己系所的規範與指導教授意見為準。

## 1. 判斷在哪一段

使用者的訊息看得出手上有什麼，就直接判斷；看不出來才問一句：「你現在手上有什麼：還沒有方向、寫得出一句話的研究想法，還是已經在寫章節？」

| 手上有什麼 | 階段 | 下一個 SKILL | 可以這樣開口 |
|---|---|---|---|
| 什麼都沒有，或只有一個大領域 | 找方向 | `research-direction-finding` | 「我想做 AI 相關的，但不知道怎麼縮小」 |
| 老師給了研究計畫，要從裡面找題目 | 找方向（計畫延伸） | `research-direction-finding` | 「老師的計畫在做 X，我負責 Y，要怎麼變成我的題目」 |
| 寫得出一句話的研究想法 | 稽核題目 | `research-question-audit` | 「我想研究 A 對 B 的影響，幫我看這個題目站不站得住」 |
| 題目稽核過了，正在讀文獻、設計方法 | thesis-toolkit 不管 | 無 | 見第 3 節 |
| 正在寫或改章節文字 | 稽核寫法 | `academic-writing-discipline` | 貼一段文字，說「幫我檢查這段的寫法」 |

## 2. 什麼時候換下一段

找方向的出口條件是 `research-direction-finding` 第 5 節自己寫的；其餘兩段是依各 SKILL 的範圍推出來的轉接，原 SKILL 沒有明寫：

- **找方向 → 稽核題目**：收出一句話的研究想法就換。連續兩輪收不動，代表資訊不夠，先去讀文獻再回來，不要硬往下推。
- **稽核題目 → 往下做**：稽核報告最後的總結分「可進行」「需修正後再議」「需重新收斂」三種。「可進行」就往下。「需修正後再議」的話，先用報告最後的逐項引導把不通過的項目補完；「需重新收斂」就退回找方向。
- **稽核寫法**：沒有出口條件，章節寫一段就能檢查一段。檢查時如果發現問題出在研究問題本身（例如依變數講不清楚），回到稽核題目，改寫法解決不了。

## 4. 回應怎麼寫

回應用台灣繁體中文與全形標點，保持簡短：

1. 一句話說使用者現在在哪一段，以及從他講的哪句話判斷出來的。
2. 下一個該用的 SKILL，附第 1 節的開口範例。
3. 需求落在第 3 節的範圍時，附對應的網站頁面。

不要把三個 SKILL 的內容各講一遍。使用者的訊息已經可以直接稽核（貼了研究想法或段落），就直接叫用對應的 SKILL，不要停在指路。
