# 研究方向收斂

> 授權：本 SKILL 由網站作者原創的流程與判準以 MIT 授權釋出；引用自書籍、論文、官方網站與第三方資源的內容，著作權歸原作者，本授權不及於這些內容（詳見下方「重要聲明」）。

## 0. 套用範圍與定位

**本 SKILL 管**：
- 使用者手上什麼都沒有，或只有一個大到不能當題目的領域興趣，需要一個能實際執行的起步動作
- 把「領域 → 主題 → 子題 → 題目 → 研究問題」這個收斂漏斗做成一次推進一層的引導流程
- 每一輪把結論寫進一份進度筆記，讓使用者關掉對話之後還能接續

**本 SKILL 不管**：
- 不稽核收出來的題目站不站得住腳——收出一句話研究想法之後就交棒給 `research-question-audit`
- 不管寫作品質、因果動詞、APA 格式——那是 `academic-writing-discipline`
- 不代替使用者讀文獻，也不假裝自己搜尋過文獻。需要文獻證據才能往下走時，本 SKILL 的動作是**停下來，把檢索工作交回使用者**（見第 5 節）

**重要聲明**：本 SKILL 的收斂流程與判準，來自公開的學術方法學資源，以及台灣資管領域教師在課堂與指導場合分享的通用實務經驗。**它不代表任何特定學校、系所、期刊或指導教授的要求。** 使用者仍應以自己系所的規範與指導教授意見為準。本 SKILL 只是一個通用的收斂工具。

## 1. 前置條件檢查：先分清楚使用者是哪一種起點

第一件事不是開始問問題，是**判斷使用者屬於下列哪一種**，因為三種的處理方式完全不同：

| 起點 | 特徵 | 怎麼處理 |
|---|---|---|
| **A. 完全空白** | 說不出任何領域，或說「都可以」「老師叫我自己想」 | 走第 2 節的起步策略，先製造出「願意讀下去」的候選類別，再進第 3 節漏斗 |
| **B. 有領域興趣** | 說得出領域但大到不能當題目（「我想做 AI」「想做資安」） | 直接進第 3 節漏斗，從第二層（主題）開始收 |
| **C. 題目來自老師的計畫** | 老師有接計畫，題目要從計畫延伸 | **不要走漏斗**，見第 2.3 節——這類使用者的問題不是「我想做什麼」 |

判斷不出來就直接問使用者一句：「你現在是完全沒方向、有個大方向但不知道怎麼縮小、還是老師已經給了計畫要你從裡面找題目？」

## 2. 三條起步策略

適用於起點 A、B。三條的性質不同，**不要一次全丟給使用者**，依序建議，做完一條有結果就進漏斗。

### 2.1 策略一：從頂級期刊與研討會的主題分類找

去該領域頂級期刊或研討會的網站，看它的主題分類（期刊看 aims & scope 的 topic list，研討會看 tracks 或 call for papers），**挑出幾個自己願意點進去讀下去的類別**。

為什麼這條放第一：它把「你對什麼有興趣」這種答不出來的空問題，換成「你願意花時間讀哪一類」這種當場就能驗證的行為訊號。願意點進去讀，至少代表你有耐心在這個題目上待兩年。

- 可用的期刊與研討會清單見 `references/venues.md`（含國際與國內兩部分，國內的部分對碩士生更實際）
- 引導使用者做到「挑出 2–4 個願意讀的類別」就夠了，不要當場要他選一個
- 若使用者挑不出任何一個類別，那是有意義的訊號：可能領域選錯了，回頭問他當初為什麼進這個所

### 2.2 策略二：翻系所學長姊的論文

去系所的論文庫或圖書館系統，翻過去幾屆學長姊的碩士論文，看有沒有哪一本、或哪個主題自己比較感興趣。

這條的附帶好處比表面上大：學長姊的論文同時告訴你**可行的研究規模**（碩論做得完的大小）、**資料怎麼拿到的**（問卷發給誰、資料哪裡來）、**系所接受什麼樣的題目**。這三件事在期刊論文上看不到。

- 引導使用者記下 2–3 本「我願意讀完」的論文，以及各自吸引他的**具體那一點**（是主題？方法？還是應用場景？）
- 「吸引我的那一點」比「這本論文的題目」更有用——那才是可以延伸的東西

### 2.3 策略三：從老師的計畫延伸（性質不同，獨立處理）

看指導教授手上有沒有正在執行的研究計畫，通常可以從計畫延伸出一個子題。

**這條要跟前兩條分開看**：它本質上是「題目被指派」，不是「自己找方向」。所以：

- **不要用收斂漏斗**。漏斗是為了從大範圍收到小題目，而這裡題目範圍一開始就被計畫框住了
- 這類使用者真正的問題不是「我想做什麼」，而是**「這個計畫裡的哪一塊，能單獨撐起一篇碩士論文」**——那是可行性與獨立貢獻的判斷，不是興趣的判斷
- 正確的動作：請使用者把計畫的目標與自己被分配到的部分講清楚，寫成一句話的研究想法，然後**直接交棒給 `research-question-audit`** 去稽核它站不站得住腳

## 3. 收斂漏斗：一次推進一層

五層：**領域 → 主題 → 子題 → 題目 → 研究問題**。

**鐵則**：
1. **一輪只推進一層**，不要一次問完五層，也不要跳層
2. **每一輪都必須產出可以寫進進度筆記的具體結論**。寫不出來就代表這一輪沒有進展——換問法，不要繼續聊下去
3. 每輪結束更新進度筆記（見第 4 節），再問使用者要不要繼續下一層

每一層要問什麼、什麼樣的回答算「可以往下一層」、常見的卡住情況怎麼處理，見 `references/convergence-funnel.md`。

## 4. 進度筆記

每輪結束把結論寫進一份進度筆記，使用者關掉對話後還能接續。

- 格式用**純 markdown**，不使用任何工具的專屬語法（不用 wikilink、不用 database 欄位），**Notion 與 Obsidian 都能直接貼上使用**
- 模板見 `references/progress-note-template.md`
- 檔名建議 `研究方向進度.md`，但使用者要叫什麼都可以
- 筆記要記的不只是結論，還有**被排除的選項與排除的理由**——三個月後回頭看，「我為什麼沒選那個」跟「我選了什麼」一樣重要

## 5. 什麼時候停下來，交給誰

| 情況 | 動作 |
|---|---|
| 收出一句話研究想法 | **停止引導**，交棒 `research-question-audit` 稽核 |
| 連續兩輪收斂不動、答案繞圈 | 判定為**資訊不足**，停止追問。指示使用者去讀文獻，並提供文獻檢索的接力做法（見 `references/handoff-to-literature.md`），讀完再回來 |
| 使用者開始問「這樣寫對不對」 | 那是寫作問題，交棒 `academic-writing-discipline` |
| 使用者屬於起點 C（老師的計畫） | 見 2.3，直接交棒稽核，不走漏斗 |

**不要為了讓流程看起來有進展而硬擠**。使用者答不出來，多半是真的還不知道，而不是問題問得不夠多——這種時候正確的動作是送他去讀文獻，不是換個方式再問一次。
