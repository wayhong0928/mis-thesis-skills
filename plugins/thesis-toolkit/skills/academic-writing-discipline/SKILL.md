# 學術中文寫作品質稽核 SKILL

> **重要提醒**：以下判準是通用學術中文寫作原則的整理，不代表任何特定系所、期刊或指導教授的規定。使用前仍要對照自己系所的寫作規範與指導教授的個別要求，兩者衝突時以系所／教授為準。本 SKILL 只收錄站方原創、可獨立溯源於公開學術／方法學資源的判準，不含任何書籍、講座或未經授權的第三方框架與專有用語；如發現例外請回報。

**授權**：本 SKILL 由站方原創的判準與流程以 MIT License 釋出，可自由使用、修改、散布；引用自書籍、論文、官方文件與第三方資源的部分，著作權歸屬原作者，本授權不及於這些內容。

## 0. 套用範圍（先分清楚管什麼）

**本 SKILL 管什麼**：文字與論證品質。具體來說——
- 因果動詞有沒有越線（橫斷面研究寫成絕對因果如「導致」、或因果與相關語言前後不一致——「影響」本身有條件可用，不是一律禁止，見 `references/sentence-and-causal.md` §一）
- 句子構句是否清楚（話題有沒有漂移、有沒有中間肥大、弱動詞能不能還原、被動語態用得對不對）
- 用語是否符合台灣學術慣例（跟大陸用語的差異）
- APA 7 中文化格式對不對（內文引用、參考文獻、標點）
- 連接詞與標點是否符合台灣學術寫作慣例
- 有沒有 AI 生成文本的典型特徵
- 文獻回顧的一節是「論證」還是「報告」，論證鏈四步有沒有走完，多篇文獻擺在一起時有沒有真的對話（還是各自報告一句的證據並列）
- 緒論／導論是否完成三個功能（CARS model 的三個 move）、方法章是否同時交代 How（怎麼做）與 Why（為何這麼做）、章節結構安排有沒有常見的誤解（見 `references/chapter-structure.md`）

**本 SKILL 不管什麼**：研究設計邏輯——研究問題該怎麼問、研究缺口怎麼分類與定位、方法論選擇是否恰當、量表構念的操作化是否合理。這些屬於 `research-question-audit` SKILL 的範圍。

**分工一句話**：這個 SKILL 檢查「這段話寫得對不對、像不像人寫的、論證撐不撐得住」；`research-question-audit` 檢查「這個研究問題問得對不對、缺口抓得準不準」。兩者可以先後套用在同一份文獻回顧草稿上，互不重疊。

## 1. 互動形態

**單輪結構化輸出**，不是多輪逼問：

1. 使用者貼一段中文學術文字進來（不需要先準備檔案、不需要提供檔案路徑）。
2. 依序套用第 2 節列出的判準，一次跑完。
3. 輸出結構化問題清單（見第 4 節格式），標明嚴重程度、原句、問題、改法。
4. 不寫入任何檔案到使用者的電腦，純對話輸出。
5. 不追問使用者「要不要看某一類判準」，除非使用者主動要求只看某一塊。

## 2. 判準總覽

| 判準類別 | 檢查什麼 | 詳細規則見 |
|---|---|---|
| 因果動詞紀律 | 橫斷面研究有沒有寫成因果；主張強度是否匹配證據強度；有沒有自創路徑名稱 | `references/sentence-and-causal.md` §一 |
| 構句原則 | 一句一話題、有沒有中間肥大、弱動詞能不能還原、被動語態用得對不對 | `references/sentence-and-causal.md` §二 |
| 台灣學術用語 | 是否誤用大陸用語（一般用語、統計術語）、地區用語對照 | `references/taiwan-usage-apa.md` §一 |
| APA 7 中文化 | 內文引用格式、參考文獻格式、APA 6/7 差異 | `references/taiwan-usage-apa.md` §二 |
| 連接詞與標點 | 連接詞是否濫用、標點是否符合台灣學術慣例 | `references/taiwan-usage-apa.md` §三 |
| 去 AI 感 | AI 生成文本典型特徵、形容詞拿掉論點站不站得住、正當／不當動機的界線 | `references/ai-flavor-and-argument.md` §一 |
| 論證鏈（文獻回顧專用） | 是論證還是報告、四步論證鏈；文獻對話四測試——主語掃描、關係詞測試（同段兩篇以上文獻必須寫出關係）、伏筆兌現檢查（概念登場後有沒有被用掉）、遮住引註總檢 | `references/ai-flavor-and-argument.md` §二 |
| 常見錯誤速查 | 快速比對表，寫完後最後掃一遍用 | `references/ai-flavor-and-argument.md` §三 |
| 章節結構（緒論／方法章） | 緒論三功能（CARS model 三個 move）有沒有到齊；方法章 How 與 Why 是否都交代；文獻缺口是否誤放成獨立總結節、研究倫理是否誤放成方法章固定一節 | `references/chapter-structure.md` |

## 3. 執行步驟

1. 讀使用者貼的文字，判斷這段文字的性質（是量化研究的假說推導／討論？文獻回顧的一節？還是緒論／方法章的草稿？）——文獻回顧才套用論證鏈檢查；緒論或方法章草稿才套用 `references/chapter-structure.md`。
2. 依序對照 `references/sentence-and-causal.md`、`references/taiwan-usage-apa.md`、`references/ai-flavor-and-argument.md`、`references/chapter-structure.md`（若適用）四個檔案的判準，逐條記錄違反處，並附上原文中的具體句子（不要只講「有問題」不指出是哪句）。
3. 若文字包含文獻回顧段落，另外套用「論證鏈四步」與「文獻對話四測試」。四測試要**逐條實際執行**，不是憑印象判斷：
   - **主語掃描**：把每個句子的主語標成「文獻」或「現象／構念」，數一數比例。
   - **關係詞測試**：同段出現兩篇以上文獻時，找出寫明彼此關係（一致補強／分歧／互補／遞進／條件化）的那一句；找不到就是證據並列，要列為問題。「都支持同一個結論」不算關係。
   - **伏筆兌現檢查**：把段落裡的概念名詞列出來，逐個查最後出現位置；只出現一次又沒進入缺口論述或假說的，列為「伏筆沒兌現」。
   - **遮住引註總檢**：最後才跑，且不可單獨拿來下「論證鏈通過」的結論。
   跑完要在輸出裡逐個測試回報結果，不能只寫一句「論證鏈檢查通過」。
4. 把發現的問題分成致命／錯誤／瑕疵三級（見第 5 節判斷原則），輸出結構化清單。文獻回顧段落的輸出必須附上誠實條款：本次稽核未核對被引用文獻原文，轉述是否偏離原意需使用者自行核對。
5. 若使用者要求在本機批次檢查整份文件，告知可使用 `references/grep-checks.sh`，並說明其中哪些指令需要人工判讀、哪些應該完全跑出空結果。

## 4. 輸出格式範例

```
## 學術寫作品質稽核結果

### 致命（因果動詞越線 / 學術倫理紅線）
- 原句：「知覺易用性導致使用意圖上升。」
  問題：這是橫斷面路徑係數，用「導致」超出證據能支持的因果強度。
  改法：「知覺易用性正向影響使用意圖（β = .xx）。」

### 錯誤（用語 / APA 格式 / 論證鏈斷裂）
- 原句：「本研究通過問卷收集數據。」
  問題：「通過」「數據」是大陸用語，台灣學術寫作慣用「透過」「資料」。
  改法：「本研究透過問卷蒐集資料。」

### 瑕疵（去 AI 感 / 構句可再優化，是否要修由使用者判斷）
- 原句：「⟨具體句子⟩」
  問題：連續三句字數都落在 20–28 字，缺乏長短交錯，讀起來偏機器感。
  改法：⟨具體建議，例如插入一句 5–12 字的短句⟩

### 通過項目
- 因果動詞紀律：全篇未見越線動詞。
- APA 7 格式：內文引用格式正確，「等人」用法一致。

### 整合修改版
[把上面「致命」與「錯誤」的修法全部套用後，重新寫出一次完整、可以直接複製使用的句子——不要只留逐條局部修法，使用者要能直接拿這一版去用。瑕疵級的修法是否納入這個版本，依第 5 節的判斷原則決定，不強制。]

### 一句話總結
可用 / 需修（致命 N 處、錯誤 N 處、瑕疵 N 處）。
```

**「整合修改版」是必要輸出項，不是可省略的加分項**——使用者要的是能直接用的句子，逐條列問題只是說明過程，不能取代這一步。

---

## 5. 三個等級的判斷原則

- **致命**：橫斷面研究寫「導致」這類排除其他解釋的絕對因果陳述（除非有理論＋迴歸/路徑分析＋控制變數三條件支持，此時「影響」是可接受的寫法，見 `references/sentence-and-causal.md` §一）、同一句或同一節內因果與相關語言前後不一致、誇大原作者主張（把 "suggested" 寫成「證實」）、自創學術名詞偽裝成既有構念——這些是學術倫理層級的問題，原則上都要處理。
- **錯誤**：地區用語誤用、APA 格式明顯錯誤、文獻回顧的論證鏈缺第二步（沒有指出缺口）、同段兩篇以上文獻只有證據並列而沒寫出彼此關係、概念登場後沒被用掉也沒被劃界（伏筆沒兌現）——這些會被口試委員抓到，應該修，但不涉及倫理紅線。
- **瑕疵**：句長不夠交錯、連接詞稍微工整、hedging 略多、段落結構稍微對稱——先問一句「修這個是不是在為了假設性問題增加不必要的複雜度」，傾向讓使用者自行決定要不要動，不要每一條瑕疵都當作必修項目列出來逼使用者處理。
