# 去 AI 感、論證鏈四步、常見錯誤速查

## 一、去 AI 感

### 1. AI 生成文本的典型特徵

單獨出現不一定有問題，但多個同時出現就會被懷疑：

| 特徵 | 具體表現 | 修正方向 |
|---|---|---|
| 句長高度一致 | 每句 20–28 字，缺乏長短交錯 | 刻意插入極短句（5–12 字）與長句（35+ 字） |
| 每段結構雷同 | 「主張→證據→小結」的三明治反覆出現 | 至少 1–2 段不收束，讓觀察自然懸掛 |
| 清單式論述 | 「首先…其次…最後…」連用超過三段 | 改用其他結構，或只列兩條精寫 |
| 連接詞過度工整 | 每段開頭必有「此外」「然而」「因此」 | 偶爾不用連接詞，直接陳述 |
| 修辭反覆使用 | 「不是 X 而是 Y」句型反覆出現 | 每份檔案最多一次 |
| 破折號過多 | 中文學術文幾乎不用破折號插說 | 改逗號、括號或拆句 |
| 空泛的讚揚式結語 | 「具有重要意涵」「填補了研究缺口」 | 寫出具體的意涵或缺口內容 |
| 術語不一致 | 同一構念在不同段落用不同名稱 | 學術論文要求全篇統一一個譯名 |
| 缺乏具體數據 | 引用文獻時只說方向，不附 β 或 p 值 | 補上關鍵統計數據 |
| 同義詞輪盤 | 三句內用「主角／核心／關鍵」描述同一件事 | 選一個用到底 |
| 意義膨脹 | 「劃時代的」「具有深遠的影響」 | 改為具體事實 |
| 過度 hedging | 「可能或許大概也許」四連疊 | 選一個，最多兩個 |

### 2. 把形容詞拿掉，論點還站得住才算數

> 以理服人：論述靠證據與推理相符，不靠形容詞。

膨脹詞拿掉後論點如果站不住，那就是論點本身有問題。

| 膨脹寫法 | 具體寫法 |
|---|---|
| 具有重要的理論意涵 | 補上了⟨某段機制⟩的實證缺口 |
| 填補了研究缺口 | 過去研究以⟨A⟩為中介，本研究以⟨B⟩取代 |
| 奠定了重要基礎 | 為後續縱貫設計提供了可檢驗的序列結構 |
| 開啟了新的可能 | ⟨具體做法⟩可以區分是⟨機制一⟩還是⟨機制二⟩ |

### 3. 一個界線必須劃清楚的問題

**去 AI 感有兩種完全不同的動機：**
- **正當**：把初稿改得更有觀點、更精確、更像研究者自己的聲音。這是文字品質的提升，跟用不用工具無關。
- **不當**：用同義詞替換、打亂語法來刻意規避 AI 偵測或抄襲檢測。這在多數學校視為學術不誠實。

**降低機器味不等於能規避檢測。** 改寫工具與 AI 偵測器都不能代替學術誠信判斷；研究者應保存自己的研究與修訂紀錄，並依適用政策揭露工具使用。兩邊都不可靠，正好說明為什麼不該把賭注押在這裡。

**自我測試**：一段論述經過改寫後，如果**你自己講不清楚它的邏輯**，代表這段內容本質上還不是你的知識。此時該做的不是繼續潤飾，而是退回去重新消化文獻與資料。

## 二、論證鏈四步（文獻回顧專用）

判斷一節文獻探討寫得好不好，只要看它是**論證**還是**報告**：

| | 報告（不合格） | 論證（合格） |
|---|---|---|
| 句子的主語 | 一直是別的作者 | 是**現象**與**問題** |
| 段落功能 | 摘要別人做了什麼 | 一步一步逼出你的假說 |
| 讀完的感覺 | 知道有很多人研究過 | 知道**為什麼非做你這一題不可** |

不合格的長相：
> ❌ Davis（1989）指出⋯⋯。Venkatesh 等人（2012）也指出⋯⋯。因此本研究⋯⋯

每一小節該跑的論證鏈是固定的四步：
> ✅ **① 這個現象／構念存在**（文獻 A、B）
> → **② 但既有解釋有缺口**（文獻 C 只做到這裡，或 C 與 D 的結論互相矛盾）
> → **③ 本研究用這個方式填補**（換情境／換方法／補中介，並說明為什麼這樣補有效）
> → **④ 因此提出 Hn**

把這四步當成模板，每一節照著跑一次。**第②步是全篇最值錢的地方**；沒有第②步，第④步就沒有立足點，口試委員一定會從那裡切進來。

### 三層結構（每一節文獻探討）

1. **理論定位（1–2 段）**：這個理論解釋了什麼？在模型裡扮演什麼角色（前因？中介？框架？）？解釋到哪裡就停了？
   - ❌「X 理論由 Author (Year) 提出，是目前最具影響力的理論之一。」（空泛、AI 感重）
   - ✅「⟨某理論⟩解釋了使用者為何採納一項新科技，但它的終點是使用意圖，不及於實際的使用深度。」（第一段就講清楚這個理論能做什麼、不能做什麼）
2. **相關實證（表格 + 一段歸納）**：用表格整理同類研究，表格下方用 2–3 句話點出共通點與空白處。
3. **本節小結（1 段）**：說清楚這個理論在模型裡的角色、指出它解釋不了的部分、銜接到下一節。避免「本節回顧了 X 理論的相關文獻」這種讀者剛讀完不需要你複述的空話小結。

### 文獻是在對話還是在並列：四個可操作測試

> **方法論依據**：Webster, J., & Watson, R. T. (2002). Analyzing the past to prepare for the future: Writing a literature review. *MIS Quarterly*, 26(2), xiii–xxiii. 該文主張文獻回顧必須是 concept-centric（以概念為中心）：「概念決定一篇回顧的組織架構；相對地，有些作者採取以作者為中心的寫法，實際上只是把相關文章摘要一遍，這種做法無法整合文獻（fails to synthesize the literature）。」它提出的工具是**概念矩陣**——以文獻為列、概念為欄，必要時再依分析層次（個人／團隊／組織）切分子欄。下面四個測試把這個原則拆成可以逐句執行的動作。

**先看順序**：測試一到三是主要判準，測試四（遮住引註）只是最後的總檢。單靠測試四會漏掉最常見的失敗——**每一句都有實質內容、但句與句之間沒有關係**的證據並列，是能通過遮住引註測試的。

#### 測試一：主語掃描（抓以作者為中心的羅列）

動作：把這一段每個句子的主語標出來，分成兩類——「某文獻／某作者」或「現象／構念／問題」。

判準：
- 連續兩句以上主語都是**不同的**文獻名 → 標記為證據並列。
- 一段之內文獻當主語的句子超過一半 → 這段是報告，不是論證。

❌ 並列：
> 甲（年）以⟨樣本一⟩發現 X 現象普遍存在。乙（年）針對⟨樣本二⟩的調查也顯示 X 的比例偏高。

✅ 對話（主語換成現象，兩篇的關係被寫出來）：
> X 現象在⟨樣本一⟩與⟨樣本二⟩都被記錄到（甲, 年; 乙, 年）。兩者母體不同卻指向同一方向，「X 只是特定族群的現象」這個解釋因此站不住。

#### 測試二：關係詞測試（同段出現兩篇以上文獻時強制執行）

只要同一段落出現兩篇以上文獻，就必須有一句話明講它們之間是哪一種關係。可用的關係只有五種：

| 關係 | 判準 | 該補上的那一句長什麼樣 |
|---|---|---|
| 一致補強 | 不同樣本／方法得到同方向結果 | 「兩者樣本與方法都不同卻指向同一方向，⟨結論⟩不太可能是⟨某種偏誤⟩造成的。」 |
| 分歧 | 結論相反，或效果量差距明顯 | 「甲得到 X，乙卻得到 Y；差異可能來自⟨測量／樣本／情境⟩的不同。」 |
| 互補 | 各自涵蓋不同面向或分析層次 | 「甲處理的是⟨個人層次⟩，乙處理的是⟨團隊層次⟩，兩者合起來仍未觸及 Z。」 |
| 遞進 | 後者在前者基礎上往前推一步 | 「乙把甲的⟨某條件⟩放寬到⟨新條件⟩，但仍沿用了⟨某假設⟩。」 |
| 條件化 | 後者指出前者只在某條件下成立 | 「乙顯示甲的結果只在⟨某條件⟩下成立。」 |

**最關鍵的一條：「都支持同一個結論」不是一種關係，是同一格被填了兩次。** 兩篇文獻對本段的功能若完全相同，正確做法是**合併引註寫成一句**（「⟨現象⟩已在多個情境被記錄（甲, 年; 乙, 年）」），把省下來的篇幅拿去寫缺口。功能相同卻拆成兩句各講一遍，就是證據並列。

一句話自問：**把其中一篇刪掉，這一段會少掉什麼？** 答不出來 → 合併引註。

#### 測試三：伏筆兌現檢查（抓「提了一個概念卻沒用」）

概念矩陣除了整理文獻，也可以反過來檢查自己的稿子：**本節提到的每個概念都應該對應矩陣裡的一欄；一個只填了一格、後面再也沒出現的概念，就是沒兌現的伏筆。** （Webster & Watson 提出矩陣是為了組織文獻，並指出依分析層次切欄可以看出概念何時「溢出自身領域範圍」；把矩陣反過來當自檢工具是本 SKILL 的延伸用法，不是原文的主張。）

動作：
1. 把這一節出現的每個**概念名詞**圈出來（不含作者名、不含研究方法名）。
2. 對每個概念查它**最後一次出現的位置**。
3. 每個概念必須落到以下三種歸宿之一，否則列為問題：
   - **(a) 被用掉**：進入缺口論述，或成為假說裡的變數。
   - **(b) 被劃界**：明說「本研究不處理⟨這個概念⟩，因為⟨理由⟩」。
   - **(c) 被刪掉**。

速判規則：**只出現一次、且那一次不在本節小結或假說句裡的概念，一律列為待處理。**

❌ 伏筆沒兌現：
> ⟨某理論⟩把因應方式分成 Y 與 Z 兩類。本研究關注 Y 對⟨結果變數⟩的作用……（此後 Z 再也沒出現）

✅ 兌現（走 (b) 劃界）：
> ⟨某理論⟩把因應方式分成 Y 與 Z 兩類。本研究只處理 Y；Z 需要⟨某種資料⟩才觀察得到，橫斷面問卷設計涵蓋不了。

#### 測試四：遮住引註再讀一次（總檢，不能單獨用）

前三個測試都過了之後，把整節的引註遮起來再讀一次。遮掉之後論證還讀得通就是論證；剩下一堆「某某指出」的空殼就是報告。這一條只用來抓漏，**不能單獨拿來當「論證鏈成立」的結論**。

#### 稽核時的誠實條款

稽核一段文獻回顧時，你只看得到使用者貼進來的文字，看不到被引用文獻的原文。輸出裡必須明講一句：**本次稽核未核對被引用文獻的原文，「這段轉述有沒有偏離原作者的主張」需要使用者自己回去核對。** 不要因為文字讀起來合理，就默認引用內容忠於原文。

### 引用整合技巧

| 情境 | 做法 | 範例 |
|---|---|---|
| 多篇研究同結論 | 合併引註 | 「⟨某現象⟩與⟨某結果⟩顯著相關（作者甲, 年; 作者乙, 年）。」 |
| 研究結果分歧 | 明確呈現分歧並分析原因 | 「A 以⟨樣本一⟩發現 X，B 以⟨樣本二⟩卻發現 Y。差異可能源自……」 |
| 引用經典定義 | 一次給完，後續不再重複 | 「⟨作者⟩（年）把⟨構念⟩定義為……」之後直接用該術語 |
| 連續以「Author (Year)」開頭 | 最多兩段，第三段必須換開法 | 以現象、觀察、反問或短句開頭 |

### 寫完每一節後的三個自問

1. 你為什麼用**這個理論**而不用別的？（替代方案的回應）
2. 這個理論有什麼**限制**是你還沒處理的？（研究限制的預先處理）
3. 你的**操作型定義**跟原始定義有什麼差異？為什麼？（構念效度的防禦）

如果這三個問題都能在文獻回顧的敘述中找到答案，這一節就寫得夠紮實了。

## 三、常見錯誤速查表

| 錯誤 | 正確 | 類型 |
|---|---|---|
| 數據收集 | 資料蒐集 | 大陸用語 |
| 被試 | 受試者 / 填答者 | 大陸用語 |
| 回歸分析 | 迴歸分析 | 大陸用語 |
| 信息 | 資訊 | 大陸用語 |
| 通過問卷 | 透過問卷 | 大陸用語 |
| 結果表明 | 結果顯示 / 分析結果發現 | 大陸用語 |
| 筆者認為 | 本研究認為 / 研究者認為 | 過於老派 |
| 「」和 " " 混用 | 統一用「」 | 格式不一致 |
| 同一構念交替使用兩個譯名 | 全篇統一一個譯名 | 術語不一致 |
| 每段都以「Author (Year) 指出…」開頭 | 最多連續兩段 | AI 感 / 流水帳 |
| 「具有重要的理論意涵」 | 說清楚對誰、為何重要 | 空話 |
