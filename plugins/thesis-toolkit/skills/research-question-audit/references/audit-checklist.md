# 稽核可勾選清單

涵蓋：題目定案六問、六種壞題目長相、一致性檢查鏈、對抗式審查五步驟。稽核時逐條勾選，不能只給整體印象式的通過／不通過。

## 一、題目定案六問

對應 FINER 框架（Feasible 可行／Interesting 有趣／Novel 新穎／Ethical 合乎倫理／Relevant 切合）的通用檢查版本：

- [ ] **1. 一句話講清楚**：能不能用一句話講清楚要問什麼？如果需要先鋪陳三段脈絡才講得出問題本身，代表題目還沒收斂完成。
- [ ] **2. 有人在乎**：有沒有人真的在乎這個答案？回答不出「誰會用這個答案做什麼決定」的，判不通過。
- [ ] **3. 缺口分類明確**：屬於五種缺口（證據／知識／方法／理論／情境）的哪一種？必須明確指名其一；答「都有一點」視為未通過。（詳見 `gap-and-innovation.md`）
- [ ] **4. 依變數清楚**：依變數是什麼？能不能講清楚它對應的構念或可觀察的結果？講不出具體依變數的，判不通過。
- [ ] **5. 資料拿不拿得到**：需要的資料來源、樣本、量表是否存在或可蒐集？「應該找得到吧」不算通過，要有具體來源。
- [ ] **6. 時程可行＋降級方案**：兩年做得完嗎？如果原範圍做不完，有沒有降級可行方案（fallback design，範圍縮小後仍能完成的版本）？沒有降級方案的，視為時程風險未被處理。

六問全數通過才算「題目定案六問」關卡過關；任一項不通過都要具體寫出補救方向。

## 二、六種壞題目長相

逐一比對，命中任一種都要具體指出命中原因，不能只寫代號帶過：

- [ ] **① 沒有依變數的「⋯⋯之研究」**：題目停在描述一個主題領域（例如「關於 A 議題之研究」），看不出要測量或回答什麼結果。
- [ ] **② 戰線過長**：研究問題數量達 4 題（含）以上，或依變數達 2 個（含）以上，代表題目試圖同時回答太多件事，應收斂或拆分。
- [ ] **③ 變數沒有理論來源**：題目中出現的自變數／依變數／中介變數／干擾變數，找不到對應的理論或既有構念支持，像是研究者自己發明的說法。
- [ ] **④ 資料拿不到**：所需資料（母體、樣本、量表、次級資料）實際上難以取得或不存在，題目建立在不可行的資料假設上。
- [ ] **⑤ 換個名詞就是別人的論文**：把既有研究的變數換上同義詞或近似詞、研究架構完全照搬，本質上沒有新的問題意識。
- [ ] **⑥ 不可否證**：題目的答案不管資料呈現什麼結果都能自圓其說，沒有一個可能被資料推翻的具體假設。

六種皆未命中，才算通過此關卡。

## 三、一致性檢查鏈

也稱「golden thread」或研究設計對齊（alignment）：從研究目的到結論，每一環都要跟前後環咬合，中間不能斷。

**量化研究鏈**：
- [ ] 目的 → 問題：研究目的有沒有清楚地收斂成研究問題？
- [ ] 問題 → 假說：研究問題裡的每個變數關係，是否都對應到至少一條假說？
- [ ] 假說 → 架構：假說裡的變數與路徑，是否都畫進研究架構圖？架構圖裡有沒有多出研究問題沒提到的變數？
- [ ] 架構 → 分析：架構圖的路徑，是否都對應到規劃中的統計分析方法（例如迴歸、PLS-SEM 路徑分析）？
- [ ] 分析 → 結論：分析方法產出的結果型態，是否能直接回答研究問題（而非答非所問）？

**質性／DSR 研究的替換鏈**：
- [ ] 目的 → 問題：研究目的是否收斂成一個可探索的問題（質性）或可設計的問題（DSR）？
- [ ] 問題 → 資料蒐集／設計活動：問題是否對應到具體的資料蒐集方式（訪談、觀察、文件分析）或設計迭代活動？
- [ ] 資料蒐集／設計活動 → 分析／評估：蒐集到的資料或設計出的人造物，是否有對應的分析方法（如主題分析）或評估方式？
- [ ] 分析／評估 → 結論：分析或評估的產出，是否直接回應了最初的研究問題？

**使用注意**：使用者通常只會提供其中一兩環的資訊（例如只有研究問題，沒有假說或架構）。遇到資訊不足的環，標記「資訊不足以判斷此環」，並列出還缺哪幾環，不能自行腦補假說或架構內容去硬判斷。

## 四、對抗式審查五步驟

用來壓力測試一個已經想好、甚至自認為已經定案的研究問題：

- [ ] **1. 價值審查**：這個問題的答案，誰會在乎？拿到答案之後，能拿去做什麼決定或行動？講不出具體對象與用途的，價值審查不通過。
- [ ] **2. 理論解構**：支撐這個問題的理論假設，有沒有可能是錯的？找出至少一個「如果這個假設不成立，整個研究問題就站不住」的關鍵假設。
- [ ] **3. 方法論審計**：現有的方法／資料能不能真的回答這個問題？逐項檢查資料的時間結構、樣本代表性、測量工具的適配度，是否真的撐得起研究問題宣稱要回答的內容。細部判準如下：

  - [ ] **方法類型與問題型態相符**：研究問題若問「有沒有關係、關係多強、能不能預測」，該配量化方法（問卷、次級資料分析、實驗）；若問「這個現象怎麼發生的、當事人怎麼理解」，該配質性方法；若問「該怎麼設計、做不做得到」，該配設計科學研究（DSR）。DSR 問題另外檢查是否滿足 Hevner et al.（2004）提出的七項準則：(1) 產出具體人造物、(2) 問題具備實務關聯性、(3) 效用經過嚴謹評估、(4) 對現有知識庫有可辨識的貢獻、(5) 人造物的建構與評估方法本身嚴謹、(6) 曾搜尋比較過不同的替代技術手段、(7) 研究成果能同時對技術讀者與管理／實務讀者清楚溝通。若題目橫跨量化與質性（混合方法），要交代「哪一部分回答哪一個子問題、兩部分的結果如何整合」，不能只是量化與質性兩段並列而沒有整合論證。
  - [ ] **抽樣是否撐得住宣稱**：抽樣方法（機率抽樣或非機率抽樣）與母體的對應關係是否講清楚？代表性至少要能對上三件事——樣本數是否達到打算做的統計方法所需的最小樣本量（例如 PLS-SEM 等技術常有經驗法則門檻）、樣本表現是否可能與母體系統性不同、樣本的關鍵特徵分布是否與母體相近。用非機率抽樣（便利抽樣、滾雪球抽樣）的，要誠實寫出代表性受限之處，不能用「應該差不多」帶過。
  - [ ] **測量工具是否恰當**：使用的量表是既有文獻驗證過的既有量表，還是自行發展／改編的量表？既有量表要交代出處與原始信效度數據；自行發展或大幅改編的量表，至少要報告內容效度（是否經過相關領域專家審閱題項）、收斂效度與區辨效度（例如同構念題項的因素負荷量是否夠高、跨構念的負荷量是否夠低）、內部一致性信度（如 Cronbach's α 或同等係數）。改編幅度較大時要說明改編的具體理由與範圍，不能只寫「參考某量表修改」。
  - [ ] **質性研究改用對應的嚴謹性判準**：不要直接套用量化的「信效度」語彙，改檢查可信性（credibility）、可轉移性（transferability）、可靠性（dependability）、可驗證性（confirmability）四項是否都有對應的操作做法（例如三角驗證、厚實描述、稽核軌跡、反身性紀錄），這是質性研究方法學普遍採用的嚴謹性判準組合。

  > 判準來源：Hevner, Alan R., et al. (2004), "Design Science in Information Systems Research," *MIS Quarterly*（設計科學研究七項準則）；代表性抽樣與量表信效度（內容效度、收斂效度、區辨效度、Cronbach's α）判準取材自研究方法學通用教材與量表發展文獻的公開共識，非任何特定學校或指導教授的專屬框架；質性研究四項嚴謹性判準對應 Lincoln & Guba 提出、質性方法學教材普遍採用的架構。
- [ ] **4. 可行性與備胎**：兩年做得完嗎？如果做不完，降級可行方案（fallback design）具體是什麼樣子？沒有具體備案的視為風險未處理。
- [ ] **5. 具體建議**：綜合以上四步，給出下一步該做什麼的具體建議（例如：先補齊理論假設的文獻佐證、先做前測確認資料可得性、先縮小研究問題範圍等），不能只停在「有問題」而不給方向。

五步驟跑完後，總結給出「可進行 / 需修正後再議 / 需重新收斂」三選一的判定。
