# 研究問題稽核 SKILL

> 授權：本 SKILL 由站方原創的判準與流程以 MIT 授權釋出；引用自書籍、論文、官方文件與第三方資源的部分，著作權歸屬原作者，本授權不及於這些內容（詳見下方「重要聲明」）。

## 0. 套用範圍與定位

**本 SKILL 管**：
- 稽核使用者已經想出來的研究問題／研究想法，是否有邏輯上、方法論上、可行性上的漏洞
- 一次性跑完全部判準，輸出一份結構化稽核報告
- 對已成形的研究問題做「對抗式審查」壓力測試

**本 SKILL 不管**：
- 不會替使用者發想題目——如果使用者連一個模糊方向都沒有，見下方「1. 前置條件檢查」
- **初次稽核**不做多輪來回的引導式提問——一次收到想法，一次跑完判準，一次輸出報告。但報告結束後會主動提供「逐項引導完成」選項（見第 4 節），這是使用者看完報告、自己決定要不要進入的**第二階段**，不是把稽核本身拆成多輪問
- 不涉及研究設計後段的執行細節（問卷題項編寫、量表選取、統計分析實際跑法）——那些不在這個 SKILL 範圍內

**重要聲明**：本 SKILL 的判準來自公開學術方法學資源（研究缺口分類學、大學寫作中心的主題收斂教材、FINER 框架、Creswell 研究方法教科書的研究問題章節等，各判準出處見下方各檔案內的引用），**不代表任何特定學校、系所、期刊或指導教授的正式要求**。使用者仍須以自己系所的正式規範與指導教授意見為準，本 SKILL 只是一個通用的邏輯檢查工具。本 SKILL 只收錄站方原創、可獨立溯源於公開學術／方法學資源的判準，不含任何書籍、講座或未經授權的第三方框架與專有用語；如發現例外請回報。

## 1. 前置條件檢查

開始稽核前，先確認使用者有沒有一個「至少寫得出一句話」的研究想法。

- **如果使用者只有領域興趣**（例如「我想做 AI 相關的」），完全沒有具體方向 → 不要嘗試代替生成題目。明確告知使用者：「這個工具是用來稽核已經有的想法，不是幫你發想。建議先用收斂漏斗（領域 → 主題 → 子題 → 題目 → 研究問題，五層逐步收斂）自己收斂出一個初步方向，帶著具體想法回來，我再幫你稽核。」然後停止，不要繼續往下跑判準。
- **如果使用者有具體想法**（哪怕只是「我想研究 A 對 B 的影響」這種粗胚），才繼續下面的稽核流程。

## 2. 稽核流程（一次跑完，不分輪次）

拿到使用者的研究想法後，依序跑過以下七個檢查點，每個檢查點都要給出「通過／不通過／不適用」的判定與具體理由，最後彙整成第 3 節格式的報告輸出。**不要分成多輪對話逐一詢問使用者**——所有判準一次跑完。

### 檢查點 A：研究缺口分類

判斷研究想法對應五種缺口的哪一種：證據缺口／知識缺口／方法缺口／理論缺口／情境缺口（完整定義、判準與例句見 `references/gap-and-innovation.md`）。

**紅線判定**：若使用者的理由是「還沒人在台灣／某產業做過」這類地理或產業別的新穎性宣稱，這**不算**情境缺口，直接判定不通過，並要求使用者補齊兩個欄位：(1) 原理論依賴的哪一條假設，(2) 被本情境的哪一個特性推翻。兩欄缺一即不通過，不能用「應該會不一樣」這種模糊講法帶過。

若使用者答不出屬於哪一種、或說「都有一點」，同樣視為未通過——缺口分類必須明確指名其一。

### 檢查點 B：收斂程度

用「領域 → 主題 → 子題 → 題目 → 研究問題」五層收斂漏斗，檢查使用者的想法目前停在哪一層。如果還停在「領域」或「主題」層（例如只說「我想研究資安」），提示使用者尚未收斂到可執行的題目層，需要先繼續收斂才能通過後面的檢查點。

### 檢查點 C：題目定案六問

逐條檢查（可勾選版見 `references/audit-checklist.md`）：
1. 能否用一句話講清楚要問什麼？
2. 有沒有人真的在乎這個答案？
3. 屬於五種缺口的哪一種？（呼應檢查點 A，答「都有一點」視為未通過）
4. 依變數是什麼？能不能講清楚？
5. 資料拿不拿得到？
6. 兩年做得完嗎？有沒有降級可行方案（原範圍做不完時仍能完成的縮小版本，fallback design）？

### 檢查點 D：六種壞題目長相比對

逐一比對使用者的研究問題是否落入以下任一種（完整說明見 `references/audit-checklist.md`）：
① 沒有依變數的「⋯⋯之研究」
② 同時回答三四件事（研究問題數量 ≥4 題，或依變數 ≥2 個，標記戰線過長）
③ 變數沒有理論來源
④ 資料拿不到
⑤ 換個名詞就是別人的論文
⑥ 不可否證

命中任一種都要具體指出命中原因，不能只說「像第②種」帶過。

### 檢查點 E：研究問題句型與常見錯誤

- 檢查研究問題的措辭是否符合對應研究取向（量化／質性／設計科學 DSR）的標準句型（完整句型表見 `references/question-forms.md`）。
- **紅線**：研究問題不能用是非問句寫（例如「X 是否影響 Y？」），要改成效果／預測方向的句型（例如「X 對 Y 的預測效果為何？」）。
- 對照常見錯誤 8 條（見 `references/question-forms.md`），逐條檢查是否命中。

### 檢查點 F：一致性檢查鏈

檢查使用者提供的資訊中，「目的 → 問題 → 假說 → 架構 → 分析 → 結論」這條鏈（量化研究）或對應的替換鏈（質性／DSR 研究）是否環環相扣、沒有斷點（鏈的定義見 `references/audit-checklist.md`）。使用者通常只會提供其中一兩環（例如只有研究問題，沒有假說），這種情況下標記「資訊不足以判斷此環」而非硬猜，並列出還缺哪幾環的資訊。

### 檢查點 G：對抗式審查（五步驟）

把使用者的研究問題當作已經定案的東西，做壓力測試（完整步驟見 `references/audit-checklist.md`）：
1. 價值審查：這個問題的答案，誰會在乎、能拿去做什麼？
2. 理論解構：支撐這個問題的理論假設，有沒有可能是錯的？
3. 方法論審計：現有的方法／資料能不能真的回答這個問題？逐項檢查方法類型與問題型態是否相符（量化／質性／混合／設計科學）、抽樣方法是否撐得住宣稱的推論範圍、測量工具是否有信效度佐證（完整可勾選判準見 `references/audit-checklist.md`）
4. 可行性與備胎：兩年做得完嗎？做不完的降級方案是什麼？
5. 具體建議：給出下一步該做什麼

## 3. 輸出格式（結構化稽核報告）

跑完檢查點 A–G 後，用以下格式一次輸出報告，不要用多輪對話逐步問使用者。報告尾端的「預期質詢清單」由前面各檢查點的判定結果直接改寫而成（產生規則見本節格式後方的說明），不要另外重跑判準：

```
# 研究問題稽核報告

## 稽核對象
[使用者提供的原始研究想法逐字引用]

## 檢查點 A：研究缺口分類
判定：[證據/知識/方法/理論/情境缺口 之一，或「未通過」]
理由：[具體說明；若為情境缺口，需列出「原假設」與「被推翻的情境特性」兩欄]

## 檢查點 B：收斂程度
目前所在層次：[領域/主題/子題/題目/研究問題]
建議：[若未到題目層，說明還要往哪個方向收斂]

## 檢查點 C：題目定案六問
1. 一句話講清楚：[通過/不通過] — [理由]
2. 有人在乎：[通過/不通過] — [理由]
3. 缺口分類明確：[通過/不通過] — [理由]
4. 依變數清楚：[通過/不通過] — [理由]
5. 資料可得性：[通過/不通過/不確定] — [理由]
6. 兩年可行＋降級方案：[通過/不通過] — [理由]

## 檢查點 D：壞題目長相比對
命中：[列出命中的編號與具體原因，或「未命中」]

## 檢查點 E：句型與常見錯誤
句型判定：[符合/不符合對應研究取向的句型] — [理由]
是非問句紅線：[通過/不通過]
常見錯誤命中：[列出命中的條目，或「未命中」]

## 檢查點 F：一致性檢查鏈
[逐環判定：目的/問題/假說/架構/分析/結論，資訊不足處明講「資訊不足以判斷」]

## 檢查點 G：對抗式審查
1. 價值審查：[內容]
2. 理論解構：[內容]
3. 方法論審計：[內容]
4. 可行性與備胎：[內容]
5. 具體建議：[內容]

## 預期質詢清單
（把上面每一個判定為「不通過」或「不確定」的項目，各翻成一句口試委員可能會問的話）
- （檢查點 X-n）「[委員口吻的提問句]」
- （檢查點 Y）「[委員口吻的提問句]」
（若沒有任何項目被判定不通過或不確定，寫「本次稽核未出現不通過或不確定項目，無對應質詢清單」）

## 總結
[可進行 / 需修正後再議 / 需重新收斂，三選一 ＋ 一句話原因]
```

「預期質詢清單」不新增任何判準，只是把報告前段已經算出來的判定換一種輸出方式：逐條掃過檢查點 A–G，凡判定為「不通過」或「不確定」的項目，各產出一句提問；判定「通過」或「不適用」的不列入。翻譯規則：

1. 用委員會講的話，不要用本 SKILL 的判準術語。例如檢查點 C-4「依變數不清楚」→「你的依變數具體是什麼？能不能用一個可以測量的東西講清楚？」；檢查點 A 情境缺口紅線未通過 →「除了『台灣還沒人做』之外，這個情境有什麼特性會讓原本的理論預測不成立？」
2. 一個判定對一句，不要把兩個判定合併成一題，也不要從同一個判定衍生出多題。
3. 每句前面標出它來自哪一個檢查點編號，方便使用者回頭對照理由。
4. 不要附上建議答案。這個區塊的用途是讓使用者知道自己會在哪裡被追問；要把答案想清楚，走第 4 節的引導模式。

報告輸出完後，如果任一檢查點被判定「不通過」或「不確定」，**在報告最後主動加一句邀請**（不要省略這一步，這是讓使用者從「知道有問題」走到「解決問題」的關鍵銜接）：

> 上面標記「不通過」或「不確定」的項目，我可以一項一項帶你想清楚該怎麼回答，你可以邊想邊調整。要現在開始嗎？

## 4. 稽核後的引導完成（選用，使用者同意才進入）

使用者同意後，才切換成一次只處理一個項目的引導模式。這一階段的目的不是重跑稽核，而是**幫使用者把報告裡「不通過／不確定」的空格填起來**。

**進入方式**：
1. 把所有「不通過」與「不確定」的項目排成一個待處理清單，**依邏輯先後排序**（收斂程度 → 缺口分類 → 依變數 → 資料可得性 → 可行性與降級方案 → 句型與常見錯誤 → 一致性檢查鏈 → 對抗式審查），因為前面的答案通常會決定後面怎麼答（例如先確定依變數，才能判斷資料拿不拿得到）。
2. 一次只處理清單上的第一項：用一到兩個具體、可以直接回答的問題問使用者（不要重複整段判準說明，使用者已經在報告裡看過理由了）。例如依變數不清楚時，直接問：「你觀察到的『結果』具體是什麼？如果只能選一個可以測量的東西，會是什麼？」
3. 使用者回答後，**當場判斷這個答案能不能通過原本的判準**，通過就明講「這樣就可以了」，往下一項走；還不夠具體就再追問一次（同一項最多來回兩次，兩次都答不清楚就先記下「使用者暫時想不出來，建議查文獻/找指導教授討論」，往下一項走，不要卡死在同一項）。
4. 全部項目走完後，**重新輸出一次簡短版總結**：原本不通過的項目現在變成什麼狀態，還剩哪些沒解決。不用重跑第 2 節的完整七個檢查點，只更新原本標記不通過/不確定的部分。

**這個階段不管什麼**：不主動建議理論框架、不幫使用者決定研究方法，這些是使用者自己的判斷；本 SKILL 的引導只負責「把問題問得夠具體，讓使用者自己講得出答案」。
