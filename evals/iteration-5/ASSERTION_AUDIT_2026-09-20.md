# assertion 覆核（2026-09-20）

iteration-5 跑完後，`academic-writing-discipline` 有三條 assertion 是兩臂都判不通過的。
兩臂同時失手有兩種解釋：SKILL 真的抓不到，或者 assertion 假定的正確答案跟案例文本對不上。
這份文件記錄覆核結果。**三條 assertion 都還沒改**，改動會變更評測的正確答案，留待決定。

## 方法與獨立性但書

派一個 subagent 做，作業順序強制：先讀 `references/ai-flavor-and-argument.md` 與案例 prompt，
自己判完並寫檔落盤，才准去看四份 `response.md`。這是為了避免它看了模型回應再回頭湊答案。

**獨立性有折扣**：原訂派 opus（跟評分者的 sonnet 換模型），但當天 opus 額度用盡，改派 sonnet。
與評分者同模型，只靠任務框架差異（評分者是「照 assertion 評回應」，這個是「反過來質疑 assertion」）
拉開獨立性。依 `dispatch-template` 的多樣本評審判準，這比換模型弱，結論的可信度要打折看。

主對話在派工前先自己寫下了判斷，事後對照：a2 的結論與理由一致；a5 的結論一致但主要理由不同，
且主對話原本提的一個理由被覆核推翻（見下）；a3 主對話沒有形成明確判斷。

## 三條結論

### eval-3a 的 a3：assertion 正確，SKILL 確實漏抓

段落裡有一句完整子句明講了兩篇文獻的關係：「但其後設分析納入的研究樣本以在職員工為主，
尚未有研究檢驗學生族群……」。這是可指認的遞進／條件化關係，a3 用的「缺口延伸關係」是它的白話說法。

with_skill 只給「勉強通過」，without_skill 根本沒做關係辨識。兩臂都沒把這條關係講到位。
這一條是 SKILL 的真實不足，不是 assertion 的問題。

### eval-3a 的 a5：assertion 的正確答案寫錯了

a5 假定這段「應判為可用或僅瑕疵等級」。但段落第一句自己就矛盾：

> 並依評估結果採取問題焦點因應、情緒焦點因應或迴避因應等不同的因應方式，
> **其中迴避因應屬於情緒焦點因應的一種**

前半句把三者並列，後半句說迴避因應是情緒焦點因應的子類。同一句話裡自相矛盾，
純靠文本就能判定，不需要查任何原始文獻，符合 `SKILL.md` §5 的「錯誤」等級。
四份回應裡有三份獨立抓到這一點（eval-3b 的 prompt 共用同一句開場白）。

所以「可用或僅瑕疵」這個門檻本身不成立，正確門檻應是「需修但範圍有限」。這代表案例從
iteration-3 拆成「乾淨版」時，排掉了原本的致命缺口，卻在改寫中新引入了一個沒被注意到的分類矛盾。

**但 a5 想防的那個假陽性方向是對的。** 它要防的是把「求助行為」的操作化誤判為銜接斷裂，
而缺口敘述已從「是否也以迴避因應為主」放寬成「是否同樣依循此一評估與因應歷程」，
求助行為屬於因應行為之一，這個過渡站得住。兩臂都把它當主要缺陷扣分，那部分是模型真的誤判。

主對話原本提出的另一個理由（引用證據講迴避因應、本研究觀察求助行為，兩者對不上）
被覆核推翻，理由就是上面這條放寬敘述。構念用詞不一致（technostress 與科技焦慮）則成立，
但只到瑕疵等級，單獨不足以斷鏈。

### eval-3b 的 a2：assertion 問錯判準

a2 要求關係詞測試把兩篇文獻判成「證據並列」。但段落原文自己寫了「分別從單一群體的縱貫追蹤
與跨研究的普遍性證據」，方法與樣本互異、指向同方向，這是一致補強關係，關係詞測試本身過關。

真正的缺陷是拿較窄的宣稱（焦慮偏高）去支撐更強的宣稱（模型適用），屬於陳述強度偷換，
而這條已經由同案例的 a1 完整覆蓋。with_skill 的回應明確寫了「關係詞：過關……但過關不代表
結論強度合理」，做出了正確區分，與 a2 預設答案相反。

建議刪除 a2，把「關係詞測試過關」併進 a1 當前提，不要留兩條掛在不同判準名下卻測同一件事的 assertion。

## 最關鍵的一點：這三條都不影響 delta

三條爭議 assertion 全部是**兩臂同時失敗**，所以無論怎麼裁決，它們對 with 減 without 的差距貢獻都是零。

AWD 四個案例共 20 條 assertion，兩臂判定不同的只有 2 條：

| case | assertion | with | without | 影響 delta |
|---|---|---|---|---|
| eval-1 | a2（「存在」濫用） | pass | fail | 是 |
| eval-2 | a1（由於…因此易爆句型） | pass | fail | 是 |
| eval-3a | a3、a5 | fail | fail | 否 |
| eval-3b | a2 | fail | fail | 否 |
| 其餘 15 條 | | 兩臂相同 | | 否 |

**結論：AWD 的 +0.10 不是被壞掉的 assertion 壓低的。** 修 assertion 會改變絕對通過率，
不會改變效益差距。而且那 2 條有差的裡面，eval-2 a1 是在 SKILL 根本沒被叫用的情況下贏的
（見 `eval-2-bloated-middle-sentence/trigger_probe/`），屬於兩次獨立執行之間的隨機差異。

扣掉那一條，AWD 在 20 條 assertion 裡真正贏過 baseline 的只有 1 條。
