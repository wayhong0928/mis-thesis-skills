# iteration-7 測試規格：academic-writing-discipline 0.4.0 與 0.4.2

> 時間軸：2026-10-05 22:40 建立。決策規則（第五節）在看到任何結果之前寫定，跑完不改。

## 一、要回答的問題

0.4.1、0.4.2 只改了 academic-writing-discipline，而且兩版都沒有跑評測（見 `plugins/thesis-toolkit/CHANGELOG.md`）。這輪回答：

1. 0.4.2 有沒有比 0.4.0 好，至少不能變差？
2. 0.4.1、0.4.2 新加的幾項規則，在模型上有沒有效果？
3. 0.4.2 對沒裝 skill 的效益還在不在？

## 二、實驗矩陣

- 13 題 × 3 臂 × 4 次＝156 次執行，評分另計。

## 五、決策規則（跑之前定好，跑完不改）

發布 0.4.2（打 tag、建 GitHub release）要同時符合 1 到 4：

1. **不退步**：Sonnet 與 Opus 上，0.4.2 的 outcome 通過率（不含 tests_change）都不低於 0.4.0；負向斷言的失敗次數（假陽性）不多於 0.4.0。
2. **逐題不退步**：任一題 0.4.2 平均比 0.4.0 少 1 條以上 outcome 斷言時，讀原文找原因。是 0.4.1／0.4.2 某項改動造成的，那一項退回或修改後重測，重測通過前不發布；是評分或斷言的問題，記進裁決。
3. **比較好**：Sonnet 與 Opus 上，0.4.2 的 outcome 通過率（含 tests_change）都高於 0.4.0。
4. **skill 仍有效益**：Sonnet 與 Opus 上，0.4.2 減沒裝的差距都至少 +0.05。

另外：

5. 某條 tests_change 斷言，0.4.2 在 Sonnet 3 次裡少於 2 次通過、或 Opus 沒通過，那一項改動在 README 與 CHANGELOG 寫明「評測沒有顯示效果」。只要沒有造成 1、2 的退步，就不擋發布。
6. README 的評測段落補上 iteration-7 的數字，寫清楚比的是哪兩個版本、哪兩個模型、每題幾次。

## 六、0.4.3 重測（2026-10-05 晚補，跑之前寫定）

第五節的判定是 0.4.2 不發布（見 `VERDICT.md`）。0.4.3 只修 n7 的副作用（`plugins/thesis-toolkit/CHANGELOG.md`），使用者要求做必要的測試就好，所以不重跑全部 13 題。

- 新增一臂 `v0.4.3`（分支 `fix-0.4.3` 的 worktree），執行與評分設定同第四節。
- n7：Sonnet 6 次、Opus 3 次。這題是修正的目標，0.4.2 在這題出錯的機率是 Sonnet 3 次裡 1 次、Opus 1 次裡 1 次，次數要夠多才看得出修好了沒有。
- 回歸題：n1、n4、n6、n8、n10，Sonnet 3 次、Opus 1 次。選這五題，是因為它們都含文獻引用又要出修改稿，最可能被「修改稿照原句保留」影響。其餘 7 題沒有轉述別人研究發現的內容，沿用 0.4.2 的結果。

判定（四條都過才建議發布，最後由使用者決定）：

1. n7 a2：0.4.3 全部通過（Sonnet 6/6、Opus 3/3）；n7 a1 也全部通過（待核對清單沒有被修正弄掉）。
2. 回歸題：每題 0.4.3 平均 outcome 通過條數，不比 0.4.0 少 1 條以上；假陽性不多於 0.4.0。沒載入 skill 的執行另外標出，與修正無關的觸發失誤要分開說明。
3. 合併表：重測過的 6 題用 0.4.3 的結果，其餘 7 題沿用 0.4.2，依第五節第 1、3、4 條的算法算出 Sonnet 與 Opus 的數字，與 0.4.0 比。n7 的 Opus 用 3 次的平均。觸發失誤若讓 Opus 不過，同時列出只算有載入 skill 的數字，由使用者判斷。
4. 0.4.3 的修改稿抽查：回歸題中，n8 的 Bandura 歸屬錯誤、n10 的 Hair 與 Zhao 引用，修改稿的處理方式要在回報裡逐次列出（保留並標待核對，或改寫），確認修正沒有讓已指出的錯誤原樣留在修改稿而不加標註。
