# 研究問題稽核報告

## 稽核對象
RQ1：大學生的科技焦慮是否正向預測其生成式AI求助頻率？
RQ2：大學生的程式設計自我效能是否影響其生成式AI求助頻率？
背景：橫斷面問卷，約250人，依據壓力因應理論，控制性別與年級。

## 檢查點 A：研究缺口分類
判定：不確定
理由：使用者只說明了理論依據（壓力因應理論）與控制變數，沒有指出這兩條路徑分別對應五種缺口（證據／知識／方法／理論／情境）中的哪一種。特別要注意：如果理由是「還沒人研究大學生對生成式AI的求助行為」，這屬於地理／新穎性宣稱，不構成情境缺口，需要補齊「原理論依賴的哪一條假設」與「被本情境的哪一個特性推翻」兩欄才算數。

## 檢查點 B：收斂程度
目前所在層次：研究問題層
兩題都已經寫出明確的自變數、依變數與（部分）方向，屬於可執行的研究問題層級，不需要再往上收斂。

## 檢查點 C：題目定案六問

1. 一句話講清楚：通過 — 兩題都能一句話講完要問什麼。
2. 有人在乎：不確定 — 使用者未說明這個答案誰會拿去做什麼決定（例如教學單位調整AI輔助教學政策、系所設計程式課程支援機制等），需要補充。
3. 缺口分類明確：不通過 — 同檢查點A，未指名屬於哪一種缺口。
4. 依變數清楚：通過 — 依變數統一為「生成式AI求助頻率」，兩題共用同一個依變數，尚屬清楚；但建議說明「求助頻率」的操作型定義（例如量表題項是「每週使用次數」還是「使用頻率量表分數」）。
5. 資料拿不拿得到：通過 — 已說明約250人橫斷面問卷，資料蒐集規劃具體。
6. 兩年可行＋降級方案：不確定 — 未提及時程規劃，也未說明若樣本數不足或回收率不理想時的降級方案。

## 檢查點 D：壞題目長相比對
命中：未命中
說明：兩題共用同一依變數（生成式AI求助頻率），由兩個不同自變數（科技焦慮、程式設計自我效能）分別預測，這是同一依變數的多重迴歸設計，不算②戰線過長（戰線過長是指出現多個各自需要獨立理論解釋的依變數）。但兩個自變數是否能被同一套「壓力因應理論」一致地解釋，是檢查點G會處理的理論一致性問題，與這裡的「壞題目長相」判準不同層次。

## 檢查點 E：句型與常見錯誤

句型判定：符合量化研究「直接效果」句型，理由見下。

是非問句紅線：
- RQ1「是否正向預測」：通過 — 動詞已帶方向（正向），不算命中紅線。
- RQ2「是否影響」：不通過 — 命中紅線。「影響」沒有交代正向或負向，是可以用「是」「否」回答完的問句，需要改寫為「大學生的程式設計自我效能是否正向（或負向）預測其生成式AI求助頻率？」，並在後續假說中交代預期方向。

常見錯誤命中：
- 第1條（是非問句寫法）：RQ2命中，理由同上。
- 其餘7條：資訊不足以判斷（使用者尚未提供假說、研究架構等文字），暫不列為命中，但需要留意：一旦你把RQ2改成有方向的句子後，記得在假說中避免寫成「有顯著影響」這種把統計顯著性與效果方向混為一談的講法（第4條）。

## 檢查點 F：一致性檢查鏈

- 目的 → 問題：可判斷，通過 — 從背景資訊（壓力因應理論、控制變數）可以合理推知研究目的是檢驗科技焦慮與程式設計自我效能對求助行為的預測力。
- 問題 → 假說：資訊不足以判斷 — 尚未提供假說文字。
- 假說 → 架構：資訊不足以判斷 — 尚未提供研究架構圖。
- 架構 → 分析：資訊不足以判斷 — 尚未說明統計分析方法（例如是否為階層迴歸，以性別、年級為第一區塊，科技焦慮與自我效能為第二區塊）。
- 分析 → 結論：資訊不足以判斷 — 同上。

## 檢查點 G：對抗式審查

1. **價值審查**：不確定。生成式AI在高等教育中的使用行為是目前受關注的議題，但使用者尚未明講「誰會用這個結果做什麼決定」——是要給系所調整程式設計課程的AI輔助政策？還是給輔導單位設計因應科技焦慮的支持措施？建議明確寫出至少一個具體的應用對象與用途。

2. **理論解構**：這是本次稽核最需要留意的一點。壓力因應理論（stress-coping theory，Lazarus & Folkman 的評估—因應架構）通常把「科技焦慮」放在初級評估（威脅知覺）的位置，把求助行為視為一種因應策略，RQ1的理論鏈相對清楚。但「程式設計自我效能」要放進同一套理論裡，需要明確定位——如果是放在次級評估（對自身因應資源的評估），那麼理論上自我效能較高的人可能因為「覺得自己不太需要外部協助」而求助頻率較低（負向路徑），也可能因為「更有把握有效利用AI工具」而求助頻率較高（正向路徑），兩種機制在文獻上都講得通，但需要研究者明確指出採用哪一種、為什麼。目前RQ2只寫「是否影響」，反映出這個理論定位可能還沒想清楚——這正是紅線判定命中的根本原因，不只是措辭問題。

3. **方法論審計**：
   - 方法類型與問題型態相符：通過，橫斷面問卷搭配迴歸分析，適合回答「預測力」型的量化問題。
   - 抽樣是否撐得住宣稱：不確定 — 未說明是機率抽樣還是便利抽樣（例如透過特定課程或系所發放問卷），也未確認250人是否達到規劃分析方法（例如階層迴歸、或若涉及潛在變數用SEM/PLS-SEM）所需的最小樣本量。
   - 測量工具是否恰當：不確定 — 未說明「科技焦慮」「程式設計自我效能」「生成式AI求助頻率」三個構念分別使用既有量表還是自編量表，也未提供信效度資訊。

4. **可行性與備胎**：不確定 — 資料蒐集規劃具體（250人問卷），時程風險相對較低，但未明說是否已完成蒐集、預計何時完成分析，也未提及若回收率不足或量表信效度不佳時的降級方案。

5. **具體建議**：
   - 優先把RQ2改成有方向的句子，並回頭想清楚程式設計自我效能在壓力因應理論中的定位（次級評估的因應資源），據此決定預期方向是正向還是負向。
   - 明確指名這兩題分別對應哪一種研究缺口。
   - 補上一句話說明研究目的的應用價值（誰會用這個結果）。
   - 說明抽樣方法與測量工具（量表出處、信效度），尤其是「生成式AI求助頻率」若無現成量表，需要交代自編題項的內容效度做法。
