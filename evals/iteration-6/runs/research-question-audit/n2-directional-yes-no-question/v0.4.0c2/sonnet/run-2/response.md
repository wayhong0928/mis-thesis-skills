# 研究問題稽核報告

## 稽核對象
RQ1：大學生的科技焦慮是否正向預測其生成式AI求助頻率？
RQ2：大學生的程式設計自我效能是否影響其生成式AI求助頻率？
背景：橫斷面問卷，約250人，依據壓力因應理論，控制性別與年級。

## 檢查點 A：研究缺口分類
判定：不確定
理由：使用者說明採「壓力因應理論」作為框架，但未指名本研究屬於五種缺口的哪一種。另外要提醒一個理論定位上的落差：科技焦慮較容易對應壓力因應理論中「評估（appraisal）」或情緒反應的構念，但程式設計自我效能源自 Bandura 的自我效能理論，並非壓力因應理論的原生構念。若要把兩者放進同一個理論框架下的研究，需要在文獻回顧中交代程式設計自我效能如何被壓力因應理論涵蓋（例如作為次要評估階段影響因應選擇的個人資源），否則 RQ2 的理論定位會顯得游離。此點也連動到檢查點 C-3 與 D-③。

## 檢查點 E：句型與常見錯誤
**RQ1**：句型判定：符合量化直接效果句型（已含方向「正向預測」）— 通過。是非問句紅線：通過（動詞已帶方向，不算命中）。
**RQ2**：句型判定：不符合 — 「是否影響」沒有交代效果方向、強度或形狀。是非問句紅線：**不通過**，命中紅線。
建議改法：「大學生的程式設計自我效能對其生成式AI求助頻率的預測效果為何？」或先確認預期方向後改為「是否負向預測」等具方向句型。
常見錯誤命中：第1條（是非問句寫法）命中於 RQ2；其餘7條依現有資訊未命中或不適用（假說、架構尚未提供，无法判斷第4、8條）。

## 檢查點 G：對抗式審查
1. **價值審查**：使用者尚未明講「誰會在乎、能拿去做什麼決定」。可能候選對象（程式設計教師、學輔單位）需自行確認，否則此項無法算通過。
2. **理論解構**：關鍵可能有錯的假設——壓力因應理論通常區分「問題焦點因應」（解決問題）與「情緒焦點／逃避因應」（迴避壓力源）。本研究把「向生成式AI求助」預設為一種（正向的）因應行為，但求助AI也可能是一種逃避獨立解題、迴避焦慮情境的行為，兩者理論預測的效果方向可能不同，甚至互相抵銷。若不先釐清求助行為在因應分類中的定位，RQ1「正向預測」的方向假設可能站不住。另外，程式設計自我效能能否被涵蓋在壓力因應理論的評估歷程中（作為個人資源），仍待理論回顧補強（同檢查點 A）。
3. **方法論審計**：方法類型（量化問卷測預測關係）與問題型態相符，可行。抽樣：N≈250，若為便利抽樣需誠實說明代表性限制；若計畫用迴歸／階層迴歸（2個自變數＋2個控制變數）分析，樣本量通常足夠，但建議說明依據（如經驗法則或統計檢定力估算）。測量工具：三個構念的量表出處與信效度數據未提供，尤其「生成式AI求助頻率」若為自編或改編量表，需報告內容效度、收斂/區辨效度與內部一致性信度。
4. **可行性與備胎**：問卷設計與樣本數已規劃，基本可行；但未見時程規劃與回收率不足時的備案，風險尚未處理。
5. **具體建議**：(a) 在文獻回顧中明確定位缺口類型，並說明程式設計自我效能如何被壓力因應理論涵蓋；(b) 釐清依變數「生成式AI求助頻率」的測量情境範圍，確認與兩個自變數的領域是否對齊；(c) 將 RQ2 改寫為具方向性句型，並在假說中依理論推導出預期方向；(d) 確認三個構念採用的量表出處與信效度，新興構念（求助頻率）若需自編量表應規劃內容效度審閱；(e) 補齊假說、研究架構與統計分析計畫，讓一致性檢查鏈完整可驗證。

總結判定：可進行 / **需修正後再議** / 需重新收斂 → **需修正後再議**。題目已收斂到可執行的研究問題層，依變數與樣本規劃具備基礎，但理論缺口定位、RQ2 句型、量表信效度資訊、以及程式設計自我效能在壓力因應理論下的角色，都需要補強後才站得住腳。
