## 檢查點 G：對抗式審查
1. **價值審查**：目前講不出具體受益對象與用途。建議想清楚：這個結果是要說服誰（例如系所教學單位）在教學設計上做什麼改變？
2. **理論解構**：關鍵假設是「科技焦慮會驅動求助行為（而非迴避行為）」——壓力因應理論本身並不保證焦慮一定導向「求助」這種主動因應，也可能導向迴避、放棄或否認等消極因應策略。如果這條假設不成立（例如高焦慮學生反而更少求助、更依賴自己摸索或乾脆放棄任務），RQ1 的「正向」方向就站不住，這是口試最可能被挑戰的點。RQ2 同樣需要說明：自我效能高的學生求助頻率應該更高（善用工具、策略性求助）還是更低（不需要協助）？兩種理論解釋都存在，你需要在文獻中選邊站並說明理由。
3. **方法論審計**：
   - 方法類型與量化預測式問題相符，橫斷面問卷設計合理。
   - 抽樣方法未說明（機率抽樣或便利抽樣？），n≈250 對於控制2個變項＋2個自變項的階層迴歸而言，樣本量大致足夠，但若還有其他分析（如探索性因素分析）需個別檢查樣本量門檻。
   - 測量工具未說明：「科技焦慮」「程式設計自我效能」「生成式AI求助頻率」是採用既有量表還是自行編製？既有量表需交代出處與原始信效度；自編量表需要報告內容效度、收斂／區辨效度與內部一致性信度。這是口試必問的項目。
4. **可行性與備胎**：以已有250人問卷資料而言風險不高，但仍建議先確認若某一分量表信度不佳需要刪題後，樣本是否仍足夠支撐分析。
5. **具體建議**：
   - 先確定「生成式AI求助頻率」的操作型定義與測量方式。
   - 針對 RQ2，補齊自我效能在壓力因應理論中的理論定位，或考慮改用能同時涵蓋兩構念的理論框架（例如加入 Bandura 自我效能理論作為輔助框架，說明兩理論如何整合）。
   - 改寫 RQ2 句型，明確指出預期方向。
   - 補充量表出處與信效度資訊、抽樣方法說明。

**總結：需修正後再議** — 主要卡點在 RQ2 與壓力因應理論的理論鏈接尚未說清楚、RQ2 句型違反是非問句紅線、以及依變數操作型定義與測量工具資訊不足；這些都是可以透過補充文獻與定義解決的問題，不需要重新收斂題目方向。
