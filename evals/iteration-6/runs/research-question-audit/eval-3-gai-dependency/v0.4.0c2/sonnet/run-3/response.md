# 研究問題稽核報告

## 稽核對象
「我的研究主題是探討學生學習程式設計時對GAI依賴的情形」

## 檢查點 A：研究缺口分類
判定：不確定
理由：使用者沒有指出這個研究對應五種缺口（證據／知識／方法／理論／情境）中的哪一種，也沒有提供任何文獻對照的說明。目前無法判斷貢獻定位在哪裡，需要使用者補上：現有文獻在這個主題上已經做到哪裡、還缺什麼。

## 檢查點 B：收斂程度
目前所在層次：子題
建議：這句話已經指定了母體（學習程式設計的學生）與現象（對GAI依賴），比「主題」層更具體，但還停在「描述一個現象」的階段，尚未收斂出具體要測量的結果（依變數）與研究問題句。需要繼續往「題目」與「研究問題」層收斂，例如先決定「依賴」要測的是什麼（頻率？程度？對哪些任務的依賴？依賴對什麼結果的影響？）。

## 檢查點 C：題目定案六問
1. 一句話講清楚：不通過 — 目前是主題描述句，不是一個可以被回答的問句。
2. 有人在乎：不確定 — 可以合理推測教師、課程設計者會在乎，但使用者沒有明講「誰會用這個答案做什麼決定」。
3. 缺口分類明確：不通過 — 對應檢查點 A，尚未指名。
4. 依變數清楚：不通過 — 「依賴的情形」是模糊描述，看不出具體要測量的構念（是依賴程度？依賴頻率？依賴後對程式能力/學習成效的影響？）。
5. 資料可得性：不確定 — 未提及要用問卷量表、學習歷程log、訪談還是其他方式蒐集資料。
6. 兩年可行＋降級方案：不確定 — 未提及研究規模與時程規劃，也沒有降級方案。

## 檢查點 D：壞題目長相比對
命中：①沒有依變數的「⋯⋯之研究」——「探討⋯⋯依賴的情形」與「⋯⋯之研究」是同一種問題形狀，都只圈出了一個現象領域，沒有講出具體要測量或回答的結果。

## 檢查點 E：句型與常見錯誤
句型判定：不適用 — 使用者尚未寫出研究問題句，目前只是主題敘述。
是非問句紅線：不適用（尚未寫出研究問題句）
常見錯誤命中：類似第 7 條「問題句寫成目的句」的前身狀態——這句話連目的句的結構都還沒有，是更前一步的主題描述，同樣需要先轉換成一個可回答的問句。

## 檢查點 F：一致性檢查鏈
資訊不足以判斷此環：使用者只提供了「研究目的／主題」這一環，沒有提供研究問題句、假說、架構或分析方法，因此問題→假說→架構→分析→結論這幾環都無法判斷。

## 檢查點 G：對抗式審查
1. 價值審查：可以想像的關心對象是程式設計課程教師、課程設計者、教育政策制定者——他們可能想知道「該不該限制/如何引導學生使用GAI」。但使用者尚未明講具體對象與這個答案能支持什麼決定，建議先想清楚。
2. 理論解構：這類題目常見的理論候選包括自我調節學習理論（self-regulated learning）、認知卸載（cognitive offloading）、科技依賴／過度信任（automation bias, over-reliance）等。目前使用者未指定理論框架，需要先選定一個理論，並找出「如果這個理論的核心假設不成立，研究問題就站不住」的那一個假設。
3. 方法論審計：研究問題型態尚未定案（是要問「依賴程度多高」偏量化，還是「學生為什麼／如何依賴」偏質性），無法判斷該配哪種方法。抽樣、測量工具（例如是否要用或改編既有的「GAI依賴量表」）都要等依變數與方法取向確定後才能評估。
4. 可行性與備胎：不確定，需視最終研究問題範圍與方法而定。若做量化問卷調查，需先確認能否取得足夠樣本數的程式設計課程學生；若做質性訪談，需確認能否取得足夠受訪者與時間深度。
5. 具體建議：
   - 先把「依賴的情形」具體化成一個可測量的依變數（例如：依賴程度、依賴頻率、對特定任務類型的依賴、依賴與程式能力/學習成效的關係）。
   - 決定研究取向（量化測「依賴程度多高、跟什麼結果有關」，或質性探「學生為何、如何依賴」）。
   - 選定一個理論框架，並指出這個理論在「學生用GAI學程式設計」這個情境下，哪一條假設可能不成立（不要只用「還沒人在這個情境做過」當理由）。
   - 查文獻確認這個主題目前的缺口是「還沒人研究過」（知識缺口）還是「已有研究但結果不一致」（證據缺口），這會決定你論文開頭要怎麼寫貢獻。
