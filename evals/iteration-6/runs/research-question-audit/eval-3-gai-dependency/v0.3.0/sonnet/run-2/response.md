# 研究問題稽核報告

## 稽核對象
「探討學生學習程式設計時對GAI依賴的情形」

## 檢查點 A：研究缺口分類
判定：**未通過**
理由：未指名屬於證據／知識／方法／理論／情境缺口的哪一種。「依賴」是近年才出現的現象，直覺上像知識缺口（沒人研究過）或情境缺口（GAI 出現後的新情境），但兩者結論不同、需要的文獻回顧策略也不同，你必須先自己判斷再往下走，不能留白。

## 檢查點 B：收斂程度
目前所在層次：**主題／子題層**，尚未到題目層。
建議：「學生學習程式設計時對 GAI 的依賴」還只是一個現象領域，缺少具體的研究問題形狀。需要進一步收斂：依賴的對象是誰（大學生？特定課程的學生？）、依賴表現在什麼行為上（測驗表現？除錯能力？學習動機？）、要探討依賴的前因還是後果、用什麼方法量測「依賴」。

## 檢查點 C：題目定案六問
1. 一句話講清楚：**不通過** — 「探討⋯⋯情形」是描述性語句，讀者看不出你想問的具體問題是什麼（依賴程度多高？依賴的前因？依賴造成的後果？）。
2. 有人在乎：**不確定** — 教育現場對 GAI 依賴議題有普遍關注，但你尚未講清楚「答案能拿去做什麼決定」（例如：調整課程設計？訂定 GAI 使用規範？）。
3. 缺口分類明確：**不通過** — 呼應檢查點 A。
4. 依變數清楚：**不通過** — 「依賴的情形」不是一個可測量的構念，需要操作型定義（例如：GAI 使用頻率、對 GAI 答案的驗證行為、脫離 GAI 後的獨立解題表現）。
5. 資料拿不拿得到：**不確定** — 未說明母體、樣本來源、施測工具。
6. 兩年可行＋降級方案：**不確定** — 未提供時程規劃或降級方案。

## 檢查點 D：壞題目長相比對
命中：**①沒有依變數的「⋯⋯之研究」**。「探討學生⋯⋯依賴的情形」與「關於 A 議題之研究」屬同一種問題——停在描述一個主題領域，沒有講出要測量或回答的具體結果。

## 檢查點 E：句型與常見錯誤
句型判定：**不符合** — 目前完全沒有寫成問句，是純粹的研究目的敘述。
是非問句紅線：不適用（尚未寫成問句，無從判斷是非問句與否）。
常見錯誤命中：**第 7 條「問題句寫成目的句」**——「探討⋯⋯情形」與範例「本研究旨在探討 X 與 Y 的關係」屬同一種寫法，是目的描述而非可回答的問句。

## 檢查點 F：一致性檢查鏈
資訊不足以判斷。目前只有一句研究目的，沒有研究問題、假說、研究架構、分析方法的任何資訊，無法檢查鏈是否咬合。

## 檢查點 G：對抗式審查
1. **價值審查**：GAI 依賴議題確實有潛在讀者（授課教師、課程設計者、教育政策制定者），但「答案能拿去做什麼決定」尚未講清楚——是要調整教學法、還是訂使用規範、還是預警高依賴學生？不同用途會導向完全不同的研究問題。
2. **理論解構**：目前沒有指名任何理論框架。可能的候選理論包括自我調節學習（self-regulated learning）、認知卸載（cognitive offloading）、鷹架理論（scaffolding），但不同理論對「依賴」的定義與測量方式差異很大，選錯理論會讓後續依變數操作型定義失焦。
3. **方法論審計**：量化／質性／混合方法尚未決定。「依賴情形」若走量化，需要一個已驗證的依賴量表（目前 GAI 依賴量表較新，跨文化驗證證據可能有限，需查證）；若走質性，則要改成「學生如何經驗／詮釋對 GAI 的依賴」這種句型，而非「探討⋯情形」。
4. **可行性與備胎**：未知，需你補充時程與資料來源。
5. **具體建議**：
   - 先決定研究取向（量化找因果/預測關係，或質性探索學生的依賴經驗與歷程）。
   - 把「依賴」操作型定義成可測量的具體行為或量表構念。
   - 選定一個理論框架，講清楚這個理論的哪個構念對應到「依賴」。
   - 決定缺口類型：如果主張是「GAI 讓程式設計學習出現新的依賴現象」，這偏向知識缺口（尚無人直接檢驗）；如果主張是「既有的技術依賴理論在 GAI 情境下需要修正」，這是情境缺口，但必須依紅線規則講出「原理論的哪條假設」被「GAI 情境的哪個特性」推翻，不能只說「以前沒人研究過 GAI」。
