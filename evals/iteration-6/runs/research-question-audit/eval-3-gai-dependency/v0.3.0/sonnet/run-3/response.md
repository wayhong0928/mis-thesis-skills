# 研究問題稽核報告

## 稽核對象
「探討學生學習程式設計時對GAI依賴的情形」

## 檢查點 A：研究缺口分類
判定：未通過
理由：這句話沒有指名屬於證據／知識／方法／理論／情境缺口中的哪一種，也看不出「現有文獻在哪裡有洞」。如果打算主張是情境缺口（例如「以前依賴研究做的是網路成癮，沒人做過 GAI」），必須補齊兩欄：(1) 原理論（例如技術依賴理論、自我調節學習理論）依賴的哪一條假設，(2) GAI 這個情境的哪個特性讓那條假設不成立。目前兩欄都缺。

## 檢查點 B：收斂程度
目前所在層次：子題層（尚未到題目層）
建議：「學生程式設計學習 × GAI 依賴」是一個子題方向，但還沒有收斂出具體要問什麼。往下收斂時通常要決定：依賴的具體樣態是什麼（頻率？認知外包？過度信任輸出？）、依賴跟什麼結果變數掛勾（學習成效？程式設計自我效能？除錯能力？），以及用什麼理論框架去解釋依賴的成因或後果。

## 檢查點 C：題目定案六問
1. 一句話講清楚：不通過 — 「依賴的情形」沒有講清楚要問什麼，是描述現象還是要找成因、還是要看依賴對某個結果的影響，三種問法完全不同。
2. 有人在乎：不確定 — 教師、課程設計者理論上會關心，但目前講不出「拿到答案後具體要做什麼決定」。
3. 缺口分類明確：不通過 — 呼應檢查點 A。
4. 依變數清楚：不通過 — 「依賴的情形」不是一個可測量的構念，需要先決定是要測「依賴程度」（例如用量表測量認知依賴、情感依賴）還是「依賴對某結果的影響」（例如對程式設計能力、後設認知的影響）。
5. 資料可得性：不確定 — 若走量表調查，需先確認是否有現成的 GAI 依賴量表可用或需要自行發展；若走行為紀錄（例如 IDE 使用紀錄、AI 工具呼叫次數），需確認能否取得。
6. 兩年可行＋降級方案：不通過 — 目前完全沒有提及範圍或降級方案。

## 檢查點 D：壞題目長相比對
命中：① 沒有依變數的「⋯⋯之研究」——「探討⋯⋯情形」是這一種壞題目的典型變體，題目停在描述一個現象領域，看不出要測量或回答什麼具體結果。
其餘五種（戰線過長、變數無理論來源、資料拿不到、換個名詞就是別人的論文、不可否證）目前因題目太籠統，尚無法判斷，建議收斂後再次檢查——尤其是⑤，因為「技術依賴」在網路成癮、社群媒體依賴文獻中已有大量既有研究，換成 GAI 若只是換個工具名詞、理論架構整套照搬，會落入⑤。

## 檢查點 E：句型與常見錯誤
句型判定：不符合 — 這句話是目的描述句（「探討⋯⋯」），不是一個可以被回答的問句。
是非問句紅線：不適用（連問句都還沒寫出來）
常見錯誤命中：第 7 條「問題句寫成目的句」——「探討學生⋯⋯情形」正是典型的目的句寫法，需要先改寫成具體問句（量化例如「學生對 GAI 的依賴程度對其程式設計自我效能的預測效果為何？」；質性例如「學生如何經驗並詮釋自己在程式設計學習過程中對 GAI 的依賴？」）。

## 檢查點 F：一致性檢查鏈
資訊不足以判斷。目前只有一個主題方向，沒有研究問題、假說、架構、分析方法的資訊，無法判斷目的→問題→假說→架構→分析→結論這條鏈是否咬合。

## 檢查點 G：對抗式審查
1. 價值審查：可能的利害關係人是程式設計課程教師、課程設計者，但目前講不出「知道依賴情形之後，他們具體會調整什麼教學設計或政策」，需要使用者自己先想清楚。
2. 理論解構：尚未指定理論框架，無法解構。若採用技術依賴理論或自我調節學習理論，需要先確認該理論在「GAI 輔助程式設計學習」這個情境下，哪一條核心假設可能不成立。
3. 方法論審計：不確定。若走量化，需先決定「依賴程度」的操作型定義與測量工具（既有量表或自編），並確認信效度佐證；若走質性，需決定訪談對象與資料蒐集方式。目前兩者都未定，無法審計。
4. 可行性與備胎：未知，題目尚未收斂到能評估工作量的程度。
5. 具體建議：
   - 先決定研究取向（量化測「依賴程度對某結果的影響」，或質性探索「學生如何經驗依賴的歷程」）
   - 把「依賴的情形」拆解成具體可測量的依變數（例如：依賴程度、依賴類型、依賴對學習成效或自我效能的影響）
   - 找一個理論框架（技術依賴理論、自我調節學習理論、認知外包相關文獻等）並指出它在 GAI 情境下哪個假設可能站不住
   - 查文獻確認「AI 工具依賴對學習的影響」是否已有大量既有研究（尤其是通用 AI 助教/聊天機器人依賴的研究），避免落入⑤換個名詞
