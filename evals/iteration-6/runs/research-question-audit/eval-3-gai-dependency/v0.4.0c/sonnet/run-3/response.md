# 研究問題稽核報告

## 稽核對象
「探討學生學習程式設計時對GAI依賴的情形」

## 檢查點 A：研究缺口分類
判定：不確定
理由：使用者尚未指出這個研究要補的是哪一種缺口。可能的候選方向包括：
- 若是「目前沒人直接檢驗程式設計學習情境下的GAI依賴現象」→ 知識缺口
- 若是「現有依賴／成癮相關量表都是套用在通用GAI使用情境，沒有針對程式設計學習過程驗證過」→ 方法缺口
- 若是「程式設計學習有其特殊性（例如除錯、除工具外還需理解邏輯），原有的技術依賴理論假設不一定成立」→ 情境缺口，但**若成立需補齊紅線兩欄**：(1) 原理論依賴哪一條假設（例如「一般技術依賴理論假設任務結果可被使用者立即驗證正確性」）、(2) 程式設計學習的什麼特性推翻了這個假設。目前使用者只給了現象描述，尚未指出上述任一欄，不能自動判定為情境缺口。

## 檢查點 B：收斂程度
目前所在層次：子題（尚未到題目層）
建議：「學生對GAI的依賴」是一個現象範圍，還沒有收斂出具體的研究問題形狀。建議往下一層收斂時決定：依賴的「什麼」要被測量或解釋？是依賴的**程度**（用什麼指標）、依賴的**成因**（哪些前因變數）、還是依賴對**學習成效的影響**（依賴是自變數還是依變數）？這三種收斂方向會導向完全不同的研究設計。

## 檢查點 C：題目定案六問
1. 一句話講清楚：不通過 — 「依賴的情形」語意模糊，讀者看不出要回答「有多依賴」「為什麼依賴」還是「依賴造成什麼結果」。
2. 有人在乎：不確定 — 程式設計教育者、課程設計者可能在乎，但使用者尚未說明這個答案要被拿去做什麼決定（例如調整教學設計、評估教學介入效果）。
3. 缺口分類明確：不通過 — 對應檢查點 A，尚未指名。
4. 依變數清楚：不通過 — 「依賴的情形」不是一個可測量的構念，需要操作型定義（例如依賴程度量表分數、AI協助下完成的作業比例、脫離AI後的獨立解題成功率等）。
5. 資料可得性：不確定 — 未說明母體（哪個年級／課程的學生）、樣本來源、是否已有可用或可改編的量表。
6. 兩年可行＋降級方案：不確定 — 未提供時程規劃資訊。

## 檢查點 D：壞題目長相比對
命中：
- **①沒有依變數的「⋯⋯之研究」型**：目前句子雖非直接以「⋯⋯之研究」結尾，但「探討⋯⋯依賴的情形」是同類型的描述式措辭，沒有指出具體要測量或回答的結果，命中此類長相的核心問題（缺依變數）。
- **③變數沒有理論來源**：不確定，因使用者尚未指出「依賴」對應哪個理論構念（例如技術依賴、認知外包 cognitive offloading、自我調節學習不足等），無法判斷是否有理論支持，需要使用者補充後才能判定是否命中。

其餘（②戰線過長、④資料拿不到、⑤換個名詞就是別人的論文、⑥不可否證）：資訊不足以判斷，因目前題目過於初階，尚未寫出具體變數與資料設計。

## 檢查點 E：句型與常見錯誤
句型判定：不符合任何研究取向的標準句型 — 目前是「探討⋯⋯情形」的目的敘述句，不屬於量化的效果句型、質性的經驗詮釋句型，也不是 DSR 的人造物設計句型。
是非問句紅線：不適用（使用者還沒寫出研究問題句，目前是主題句）。
常見錯誤命中：

- **第5條（變數缺乏可辨識定義）**：「依賴」在句子中沒有對應到明確的操作型定義。

## 檢查點 F：一致性檢查鏈
資訊不足以判斷此鏈的任何一環。使用者目前只提供了接近「研究目的」層次的描述，尚未提供研究問題、假說（或質性研究的資料蒐集方式）、架構、分析方法等後續環節，無法判斷鏈是否環環相扣。

## 檢查點 G：對抗式審查
1. **價值審查**：潛在受眾（程式設計課程教師、課程設計者、教育政策制定者）存在，但目前答不出「誰會拿這個答案去做什麼決定」，因為「依賴的情形」太籠統，不知道答案要如何轉化為具體行動（例如：若發現依賴程度高，教師該如何調整作業設計？）。
2. **理論解構**：無法解構，因為目前沒有指出支撐「依賴」這個概念的理論框架（例如認知外包理論、自我調節學習理論、技術接受模型的延伸應用、或成癮／過度依賴相關理論）。選定理論框架前，無從檢驗其關鍵假設是否可能不成立。
3. **方法論審計**：不確定。若走量化，需要決定是用既有的AI依賴／使用量表改編，還是自行發展；若走質性，需說明如何蒐集學生在程式設計學習歷程中使用GAI的第一手資料（訪談、學習歷程紀錄、螢幕錄製等）。目前兩種取向都未定案，無法審計方法是否撐得住研究問題。
4. **可行性與備胎**：不確定，未提供時程與樣本規劃，也未見降級方案。
5. **具體建議**：
   - 先決定「依賴」要問的是**程度**、**成因**、還是**結果（對學習成效的影響）**，三選一或講清楚彼此的關係，這會決定依變數與研究取向。
   - 找一個具體的理論框架掛住「依賴」這個構念（例如認知外包 cognitive offloading、自我調節學習 self-regulated learning、或過度信賴 automation over-reliance 相關文獻），並指出該理論在程式設計學習情境下有什麼特殊的假設需要檢驗。
   - 決定母體與樣本來源（例如：哪個學制、哪門課程的學生），並確認測量工具（既有量表或自編）。
   - 把「探討⋯⋯情形」改寫成一個可回答的研究問題句（量化例如：「學生對GAI的依賴程度，對其程式設計獨立解題能力的預測效果為何？」；質性例如：「學生在學習程式設計過程中，如何經驗與詮釋自己對GAI的依賴？」）。
