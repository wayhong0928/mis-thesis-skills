# 研究問題稽核報告

## 稽核對象
「探討學生學習程式設計時對GAI依賴的情形」

## 檢查點 A：研究缺口分類
判定：不確定
理由：使用者尚未說明這屬於證據／知識／方法／理論／情境缺口中的哪一種。若打算主張「還沒人研究過程式設計初學者對 GAI 的依賴」，需先確認這是「根本沒人問過」（知識缺口）還是「已有研究但方向矛盾」（證據缺口）——目前 GAI 輔助學習領域已有不少相關文獻，直接宣稱「沒人做過」風險較高，建議先查文獻再定位。

## 檢查點 B：收斂程度
目前所在層次：主題／子題層（尚未到題目層）
建議：「學生學習程式設計時對GAI的依賴情形」還停在一個可以再往下問很多問題的主題範圍。需要進一步收斂：依賴的是「什麼結果」？依賴程度如何被觀察到（自陳量表？行為紀錄？作業表現？）？「學生」是哪個階段（大學程式設計課初學者？特定科系？）？依賴本身是研究的終點，還是要連結到某個後果（例如學習成效、自我效能、問題解決能力）？

## 檢查點 C：題目定案六問
1. 一句話講清楚：不通過 — 目前的句子是主題描述，不是可回答的問題；讀者看不出「答案長什麼樣子」。
2. 有人在乎：不確定 — 直覺上教育者、課程設計者會關心，但使用者尚未講出具體會拿這個答案做什麼決定（例如調整課程設計、限制 GAI 使用規範）。
3. 缺口分類明確：不通過 — 見檢查點 A。
4. 依變數清楚：不通過 — 「依賴情形」是一個籠統描述，不是可測量的構念。依賴的操作型定義是什麼？是使用頻率、求助深度、脫離 GAI 後的表現落差，還是自我報告的依賴量表分數？
5. 資料可得性：不確定 — 未提及資料來源（問卷？課程觀察？平台使用紀錄？）。
6. 兩年可行＋降級方案：不確定 — 未提及。

## 檢查點 D：壞題目長相比對
命中：① 沒有依變數的「⋯⋯之研究」的變體 — 雖然沒有用「之研究」字尾，但性質相同：「依賴情形」沒有明確指向一個可測量的結果，讀者看不出要回答什麼具體問題。

## 檢查點 E：句型與常見錯誤
句型判定：不適用 — 使用者尚未寫出研究問題句（目前是主題描述），無法對照量化／質性／DSR 句型表。
是非問句紅線：不適用。
常見錯誤命中：第 7 條「問題句寫成目的句」的更前一步——目前連目的句都還不是，只是一個主題標籤。收斂到題目層後需要重新檢查句型。

## 檢查點 F：一致性檢查鏈
資訊不足以判斷 — 使用者只提供了一個主題方向，尚無研究問題、假說、架構等後續環節的資訊。

## 檢查點 G：對抗式審查
1. **價值審查**：可以合理推測教師、課程設計者、教育政策制定者會關心「學生是否過度依賴 GAI」這個問題的答案，可能用來調整作業設計或 GAI 使用政策——但這需要使用者明確講出來，而不是我幫你腦補。
2. **理論解構**：這類題目常隱含一條假設——「使用 GAI 越多／越深，代表越依賴，且依賴會對學習不利」。這條假設本身可能不成立：例如有研究主張適度使用 GAI 反而是有效的鷹架（scaffolding），依賴不必然等同負面結果。如果研究問題要成立，需要先講清楚「依賴」在你的定義裡是中性描述還是預設負面。
3. **方法論審計**：待定——目前不知道使用者打算用量化（問卷測依賴量表）、質性（訪談學生使用經驗）還是混合方法，無法檢查方法與問題型態是否相符。
4. **可行性與備胎**：待定——尚未定案研究對象、樣本規模、資料蒐集方式，無法判斷兩年是否可行。
5. **具體建議**：
   - 先決定「依賴」要怎麼操作型定義（例如：使用頻率、任務求助深度、脫離工具後的獨立完成能力落差、自陳式依賴量表分數）。
   - 決定依賴是研究的終點，還是要連結到一個後果變數（例如學習成效、程式設計自我效能、批判思考能力）——這會決定你的研究問題形狀完全不同。
   - 查文獻確認這個主題目前的缺口類型（知識／證據／方法／理論／情境），避免用「還沒人在台灣做過」這種站不住腳的新穎性宣稱。
   - 確認研究對象範圍（大學程式設計入門課？特定系所？）。

## 預期質詢清單
- （檢查點 A）「你說這個主題有研究價值，除了『目前這個角度還沒人研究』之外，這個題目要填補的是文獻裡的哪一種空白？」
- （檢查點 C-1）「你的研究問題具體想問的是什麼？可以用一句話講出你預期的答案會長什麼樣子嗎？」
- （檢查點 C-2）「假設你做完這個研究、得到答案了，會有誰拿這個結果去做什麼決定？」
- （檢查點 C-4）「你說的『依賴』具體是指什麼？怎麼測量出一個學生『依賴』還是『不依賴』？」
- （檢查點 C-5）「你打算怎麼蒐集資料？問卷、訪談，還是平台使用紀錄？這些資料你目前拿得到嗎？」
- （檢查點 C-6）「這個研究範圍，兩年內做得完嗎？如果做不完，你有沒有想過縮小版本會是什麼樣子？」
- （檢查點 G-1）「這個答案出來之後，誰會在乎、會拿去做什麼？」

## 總結
需重新收斂 — 目前是一個合理且有價值的研究方向（GAI 對程式設計學習的影響是近年真實受關注的議題），但「依賴情形」還沒有被收斂成一個可測量、可回答的研究問題，且尚未定位研究缺口。建議先處理依變數的操作型定義與缺口分類這兩項，其他項目通常會跟著清楚起來。
