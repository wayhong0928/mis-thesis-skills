## 檢查點 G：對抗式審查
1. **價值審查**：可以想像教學實務上的用途（例如決定是否在課程初期先做自我效能鷹架、再開放AI工具），但你尚未在研究問題或動機段落中明講這一點，建議補上一句具體的「這個答案會被誰、怎麼用」。
2. **理論解構**：關鍵假設是「高自我效能 → 較少依賴AI」，但這條假設有一個值得注意的反例可能性——高自我效能的學生也可能更頻繁詢問AI，只是屬於**策略性使用**（有能力自己解，但選擇先問AI以提升效率），而不是**依賴**（沒有AI就解不出來）。你的依變數1「先問AI而不是自己先試的次數比例」單純看頻率，無法區分這兩種情況，可能把高自我效能學生的策略性使用誤判為高依賴，這也許正是既有兩篇文獻「一篇不顯著」的部分原因。這點建議在文獻回顧或限制中處理。
3. **方法論審計**：
   - 方法類型與問題型態相符：通過，屬於量化預測關係，配問卷＋迴歸是恰當的方法選擇。
   - **抽樣代表性與題目宣稱範圍不符（不通過）**：研究問題寫的是「大學生」，但樣本僅來自三門「大一程式設計課」的學生，屬於便利抽樣。結論最多能推論到「修習大一程式設計課的學生」，無法直接推論到「大學生」全體（例如已修過進階課程的高年級生、非資訊相關科系學生）。建議把研究問題或至少論文中的推論範圍陳述，收窄成「大一程式設計課學生」，或明確在限制中承認此落差。
   - **IV量表來源未確認（不確定）**：你尚未說明「程式設計自我效能」用的是哪個既有量表（例如常見的程式設計自我效能量表），還是自編。既有量表需交代原始信效度，自編則需額外驗證。
   - **DV1單題測量的信度疑慮（不確定）**：「先問AI而不是自己先試的次數比例」目前看起來是單題自陳、回溯兩週，容易受回憶偏誤影響，且單題無法計算內部一致性信度。建議想清楚這題要怎麼問（例如具體到每次作業事件、還是整體印象比例）。
   - **DV2改編量表的信效度計畫未說明（不確定）**：從問題性智慧型手機使用量表改編到AI依賴，是跨情境的構念轉移，需要交代改編幅度、內容效度（是否經專家審題）、以及預試信度（Cronbach's α）的規劃，目前只寫了「改編、6題」，稽核上不算已處理完成。
4. **可行性與備胎**：通過 — 三班已確認同意，降級方案（單班約100人）具體明確，時程風險已處理。
5. **具體建議**：
   - 決定兩個依變數是合成單一依賴分數，還是分開建模，並反映在研究問題與假說措辭上。
   - 補上IV量表的出處（既有量表或自編）與DV2改編量表的內容效度／預試信度規劃。
   - 重新設計DV1題項，降低回溯偏誤，並思考如何與「策略性使用」區隔（例如加問「即使自己有把握也會先問AI」這類區辨題項）。
   - 把研究問題或推論範圍的表述，對齊實際樣本（大一程式設計課學生），或在限制中明講此落差。
   - 補齊研究假說（含方向）與統計分析規劃，把F段落的斷點補起來。
