# 研究問題稽核報告

## 稽核對象
「大學生的程式設計自我效能對其生成式AI依賴程度的預測效果為何？」
依變數：①過去兩週寫作業先問AI而非自己先試的次數比例（自陳）；②依賴量表得分（改編自問題性智慧型手機使用量表，6題）。
缺口：既有研究多討論AI使用意願，少把依賴當結果變數；自我效能與依賴的關係目前只找到兩篇研究，方向不一致（一篇負相關、一篇不顯著）。
樣本：三門大一程式設計課，約300人，三位老師已同意；降級方案為單一門課約100人。

## 檢查點 A：研究缺口分類
判定：**證據缺口**
理由：使用者明確指出「自我效能與依賴的關係只找到兩篇研究，結果方向不一致（一篇負相關、一篇不顯著）」，這正好對上證據缺口的判準（至少兩篇文獻對同一組變數關係實證結果方向不一致）。
但要提醒：使用者同時提到「既有研究多討論使用意願，很少把依賴當結果變數」，這句話比較接近「依賴當 DV 的研究少」的新穎性宣稱，跟證據缺口是不同層次的論述。建議把這句話改寫成文獻回顧中鋪陳依賴此一構念重要性的背景句，不要跟證據缺口的理由混在一起講，否則委員可能會問「你的缺口到底是哪一種」。

## 檢查點 G：對抗式審查
1. **價值審查**：目前使用者未明講答案的具體用途，建議補上「誰會用這個結果、拿去做什麼決定」（例如授課教師是否該在課程設計中限制或引導AI使用方式）。
2. **理論解構**：自我效能理論隱含的假設是「自我效能高者更傾向獨立解決問題、較少尋求外部協助」。但這條假設可能不成立於AI情境——自我效能高者也可能因為更能判斷AI輸出品質、更懂得有效提問，而「更多使用但不依賴」，這恰好可能是兩篇既有文獻結果不一致的原因之一。建議在文獻回顧中把這個機制講清楚，這既能解釋證據缺口的成因，也能強化理論貢獻。
3. **方法論審計**：
   - 方法類型與問題型態相符：量化問卷、預測效果問題，配對正確，通過。
   - 抽樣代表性：**題目寫「大學生」，但實際抽樣僅來自三門特定學校的大一程式設計課，屬於便利抽樣**。母體宣稱與實際抽樣範圍不一致，建議把題目或研究範圍界定縮小為「修習程式設計課程之大一學生」，並在研究限制中說明無法推論到大學生整體。
   - 測量工具：
     - 自我效能量表的來源（既有量表或自編）尚未說明，需要補上出處與原始信效度。
     - 依賴量表是「問題性智慧型手機使用量表」跨領域改編到AI情境，改編幅度不小，需要報告內容效度（專家審題）、收斂／區辨效度、Cronbach's α，目前未提供。
     - 行為比例指標屬於兩週回溯的自陳資料，需留意回憶偏誤與社會期許偏誤（學生可能低報「先問AI」的比例），建議在限制中說明。
4. **可行性與備胎**：通過，已有具體降級方案（單一門課約100人）。補充：若真的只收100人，抽樣代表性會更集中在單一教師教學風格，建議在限制中提及；就統計方法而言，100人做簡單迴歸尚屬足夠。
5. **具體建議**：
   - 精簡缺口論述，明確以證據缺口為主軸，「依賴當DV較少」改寫為背景鋪陳。
   - 補充兩篇既有文獻的方法／樣本／情境，說明本研究的方法或情境改進之處，排除「換個名詞重做一次」的疑慮。
   - 釐清兩個依賴指標是同一構念的兩個面向，還是兩個不同構念，並在研究架構中講清楚。
   - 補上量表出處與信效度資訊（尤其是改編量表）。
   - 把題目或研究範圍的母體宣稱，對齊實際抽樣範圍。
   - 補上假說、研究架構、分析方法，讓一致性檢查鏈可以被完整檢驗。
