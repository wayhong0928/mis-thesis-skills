# 研究問題稽核報告

## 稽核對象
「探討台灣中小企業導入AI客服系統之研究」

## 檢查點 A：研究缺口分類
判定：未通過
理由：題目本身沒有講出任何缺口類型。如果你心裡想的理由是「台灣中小企業還沒什麼人研究這個」，這屬於情境缺口紅線明確禁止的寫法——只講了地理／產業的新穎性，沒有講出「原理論依賴的哪一條假設」和「被中小企業情境的哪一個特性推翻」這兩個必要欄位。兩欄目前都是空的。

## 檢查點 B：收斂程度
目前所在層次：子題（AI客服系統導入 ×中小企業，範圍已經比「AI應用」窄，但還沒收斂到「題目」層）
建議：子題層再往下收斂一層，需要明確指出「要問什麼」——是採用前因、導入歷程、導入成效，還是設計一套導入方法？目前這四種完全等可能，讀者猜不出你要問哪一種。

## 檢查點 C：題目定案六問
1. 一句話講清楚：不通過 — 「之研究」只標出主題領域，講不出具體要回答的問題。
2. 有人在乎：不確定 — 沒有具體問題就無法判斷誰會拿答案去做什麼決定。
3. 缺口分類明確：不通過 — 同檢查點 A，尚未指名屬於五種缺口的哪一種。
4. 依變數清楚：不通過 — 完全沒有依變數。是採用意願？導入成效？顧客滿意度？員工滿意度？系統可用性？都沒講。
5. 資料可得性：不確定 — 依變數未定，無法判斷需要什麼資料、從哪裡蒐集。
6. 兩年可行＋降級方案：不確定 — 範圍未定，無法評估時程，也就談不上降級方案。

## 檢查點 D：壞題目長相比對
命中：① 沒有依變數的「⋯⋯之研究」——題目停在描述一個主題領域，句尾用「之研究」收尾，看不出要測量或回答什麼具體結果，是最典型的這一種壞題目長相。

## 檢查點 E：句型與常見錯誤
句型判定：不符合 — 目前連一個問句都不是，比「目的句」（本研究旨在探討⋯）更弱，只是一個主題標籤。
是非問句紅線：不適用（尚未達到問句層級，無從套用是非句判定）
常見錯誤命中：第5條（變數缺乏可辨識定義，讀者看不出對應到什麼依變數）、第7條（問題句寫成目的句的更前置狀態，「之研究」是「本研究旨在探討⋯」的縮寫變體）

## 檢查點 F：一致性檢查鏈
資訊不足以判斷 — 目前只有題目文字，缺研究問題、假說、研究架構、分析方法。這四環都需要你先補上，才能判斷鏈是否環環相扣。

## 檢查點 G：對抗式審查
1. 價值審查：不確定。可能利害關係人包含中小企業主、AI客服系統供應商、政策制定者（如經濟部中小企業處），但因為問題本身還沒定義清楚，講不出「答案出來之後誰會拿去做什麼決定」。
2. 理論解構：如果你打算主張情境缺口，最常見的候選理論是 TAM／UTAUT／TOE 這類採納理論，這些理論多半假設決策者具備一定的資訊搜尋能力與資源條件。中小企業資源有限、決策者身兼多職、資訊搜尋能力受限，這條假設有可能站不住——但這需要你自己指名理論、指名假設，目前題目完全沒有觸及這一層。
3. 方法論審計：無法判斷，因為研究取向未定。若問「要不要採用、為什麼採用」→ 量化問卷（配 TAM/UTAUT 等理論構念的既有量表）；若問「導入過程怎麼經歷、遇到什麼困難」→ 質性訪談；若問「該怎麼設計一套適合中小企業的導入方法／評估工具」→ 設計科學研究（DSR）。三者的抽樣方式、測量工具、分析方法完全不同，目前無從審計。另外「中小企業」橫跨製造業、零售業、餐飲業等，同質性也是問題，需要限定產業範圍。
4. 可行性與備胎：無法判斷，範圍未定就無法評估兩年做不做得完，也就沒有降級方案。
5. 具體建議：
   - 先決定研究取向：你想問的是「為什麼／要不要採用」（量化）、「怎麼經歷導入歷程」（質性），還是「該怎麼設計一套適合中小企業的導入方法」（DSR）？
   - 決定一個具體依變數：採用意願？導入成效？顧客滿意度？
   - 若要主張中小企業情境的特殊性，具體指名理論（如 TAM/UTAUT/TOE）與被推翻的假設。
   - 限定產業範圍（例如聚焦零售業或餐飲業），避免「中小企業」內部異質性過大稀釋研究焦點。
