# 對你的研究問題的回饋

**結論：** 題目有價值，但研究問題還沒有對準你說的缺口，退路方案也有問題。建議修正後再定案。

---

## 1. 研究問題測不到你宣稱的缺口（最關鍵）

你的缺口是一個**動態、有條件的機制**：外部回饋的鷹架作用會**隨學習者能力提升而遞減**。

但你的研究問題只問「回饋詳細程度會不會影響依賴程度」，這是**主效果**。就算結果顯著，也只能說明「詳細回饋會降低（或提高）AI依賴」，無法回答「鷹架效果是否隨能力遞減」。要檢驗這個機制，至少要有下面兩者之一：

- **能力作為調節變項**：用前測或先備程式能力測驗，檢驗「回饋條件 × 能力」的交互作用。
- **時間維度**：在學期中多次測量，檢驗「回饋條件 × 時間」的交互作用。遞減是一個過程，單次測量看不出來。

**建議修正的研究問題：**
- RQ1：教師除錯回饋的詳細程度（高/低），是否影響學生使用生成式AI除錯的頻率與求助深度？
- RQ2：此效果是否受學生先備程式能力調節？
- RQ3：隨著學期進展，回饋詳細程度對AI依賴的影響是否遞減？

RQ2、RQ3 才真正對應你的理論缺口，RQ1 只是基礎。

**理論引用也要再確認：**「鷹架隨能力遞減」比較常歸在 scaffolding/fading（Wood, Bruner & Ross, 1976；Puntambekar & Hübscher, 2005）和 **expertise reversal effect**（Kalyuga 等人）。如果要掛在 Zimmerman 名下，比較站得住的是他的社會認知**多層次發展模式**（observation → emulation → self-control → self-regulation，社會支持逐層減少），而不是循環三階段模式。引用時要寫清楚是哪一個模型，否則口試時容易被挑出來。

## 2. 缺少方向性假設

你需要先說明「詳細回饋 → AI依賴」預期是增加還是減少，以及理由。兩個方向都說得通：

- **替代說**：詳細回饋已經提供答案線索，學生比較不需要問AI，所以依賴降低。
- **示範說**：詳細回饋讓學生學會怎麼拆解錯誤，於是改用AI問概念，求助深度變淺，但頻率未必下降。

這也牽涉到價值判斷：你是否把「高依賴」視為負面？「只問錯誤訊息意思」是好的自我調節，「直接要完整程式碼」才是依賴？這需要在概念定義裡寫清楚。

## 3. 依變數的可行性風險很高

「從AI工具使用紀錄量化」這個做法，實際執行時問題最多：

- 學生用的是**個人的** ChatGPT／Copilot 帳號，你很難取得紀錄。請學生自行匯出，會有選擇性分享和遺漏的問題；學生也可能改用 Gemini、Claude 等其他工具。
- Copilot 的 inline 補全幾乎沒有可用的「對話紀錄」，求助深度無從編碼。
- **可行的替代做法**：課程提供一個統一的AI除錯助手（例如包一層 API 的網頁介面），所有互動自動記錄，並告知學生課程中請使用這個工具。代價是生態效度下降，需要在限制中說明。
- **頻率要標準化**：錯誤較多或作業較難的學生自然會問得比較多，應該換算成「每次提交」或「每個錯誤」的求助次數。
- **求助深度需要編碼架構**：例如分成 1＝解釋錯誤訊息、2＝請求提示、3＝請求修正片段、4＝請求完整程式碼，並由兩位編碼者計算評分者信度（Cohen's κ）。

## 4. 實驗設計的問題

- **班內隨機分派有汙染風險**：同班同學會互相分享回饋，而且很快會發現「別人的回饋比較詳細」。這同時也是**公平性和倫理問題**，IRB 很可能會追問。
- **操弄的一致性**：80 人、整學期、每次作業都要寫高詳細回饋，老師負擔很重，品質容易走樣。需要明確的操作型定義（例如高詳細＝指出錯誤行數＋解釋原因＋提示修正方向；低詳細＝只給通過或失敗與測資結果），最好用模板，並做**操弄檢核**。
- **檢定力不足**：兩組各 40 人，檢定力 .80 時只偵測得到約 d ≈ 0.63 的中大效果。你真正關心的交互作用需要的樣本更多，80 人幾乎一定不夠。

**建議改用受試者內的交叉設計（crossover）：** 每位學生在不同作業輪流接受高、低詳細回饋，順序做對抗平衡。這樣可以一次處理上面三個問題：
- 每個人都拿過兩種回饋，公平性問題大幅減輕，IRB 比較好過。
- 每人有多筆重複觀測，用多層次模型分析，檢定力明顯提升。
- 天生就有時間維度，可以直接檢驗 RQ3。

需要注意的是延續效應（carryover），例如先拿到詳細回饋的學生可能已經學會除錯策略。可以在分析中納入順序效果，並在限制中說明。

## 5. 退路方案其實回答的是另一個問題

單一時間點的問卷研究，有三個問題：
- 沒有時間維度，**完全無法檢驗「遞減」機制**，也就是你的缺口。
- 依變數從客觀紀錄變成自陳，構念已經不同。
- 「感受到的回饋詳細程度」和「依賴程度」可能同時受第三變項影響，例如自我效能低的學生可能既覺得回饋不夠，又比較依賴AI。

所以這不是縮小版的原研究，而是另一個研究。比較好的退路是：
- 如果做不了個別隨機分派，就用上面的交叉設計，改成**以作業為單位**輪替回饋條件。
- 如果連操弄都做不了，至少做**多時間點的縱貫觀察**（例如期初、期中、期末），保留時間維度，才能部分回應缺口。
