# 研究問題稽核報告

## 稽核對象
「教師回饋詳細程度對大學生於程式設計課程中使用生成式AI除錯行為的效果」／研究問題：「教師提供的除錯回饋詳細程度，是否會影響學生對生成式AI工具的除錯依賴程度？」

## 檢查點 A：研究缺口分類
判定：**不通過（理論缺口論證不完整）**
理由：你指名的是理論缺口，但目前的陳述——「Zimmerman 主張鷹架作用隨能力提升遞減，但沒有文獻檢驗這個機制在生成式AI除錯情境下是否成立」——實際上只講了「沒人在這個新情境測試過」，這是情境缺口的新穎性宣稱句型，不是理論缺口該有的論證。理論缺口的判準要求你指出「理論的哪一個構念或路徑無法涵蓋觀察到的現象」，你目前還沒寫出這一步。

具體地說，你需要補齊：鷹架遞減假設依賴的前提是什麼（例如：學習者在外部支持減少時，沒有其他替代的外部支持來源，只能轉向自我調節）；生成式AI工具的普及，打破了這個前提的哪一點（學習者面前多了一個幾乎零成本、隨時可得的替代鷹架，低詳細回饋不一定會逼出自我調節，反而可能直接轉向AI）。這條論證你腦中大概已經有雛形，只是還沒寫進研究問題的理論陳述裡。

## 檢查點 B：收斂程度
目前所在層次：**研究問題層**，已收斂完成（有明確自變數、依變數、操作方式、樣本規劃）。

命中：③ 變數沒有理論來源（風險項，非確定命中）— 「除錯依賴程度」作為依變數，目前只有操作型定義（使用頻率、求助深度），沒有指出它對應到哪個既有心理學或教育學構念（例如「外部調節依賴」「習得無助式求助」之類）。如果一直停留在「我自己定義的兩個可量化指標」，口試時容易被問「這個構念哪裡來的」。
其餘五種：未命中。

## 檢查點 E：句型與常見錯誤
句型判定：**不符合量化研究句型**。
是非問句紅線：**不通過** — 「教師提供的除錯回饋詳細程度，是否會影響學生……除錯依賴程度？」是一個可以用「是」或「否」回答完的句子，沒有指出效果方向。應改為類似「教師回饋詳細程度（高／低）對學生除錯依賴程度（使用頻率、求助深度）的預測效果為何？」，並在文獻回顧或假說中交代方向。

常見錯誤命中：
- 第 1 條（是非問句）：命中，同上。
- 第 5 條（變數缺乏可辨識定義）：命中 — 「高詳細」「低詳細」回饋目前沒有具體操作型定義，兩組回饋實際內容上差在哪裡（例如：高詳細＝指出錯誤位置＋原因＋修正建議＋相關概念說明；低詳細＝僅指出錯誤位置）需要明確寫出來，否則沒辦法做 manipulation check。
其餘條目：未命中或資訊不足以判斷（第 8 條需要題目、問題、假說三處並列才能判斷，目前只給了問題）。

## 檢查點 F：一致性檢查鏈
目的 → 問題：通過（能從研究缺口推出問題）。
問題 → 假說：資訊不足以判斷 — 你還沒寫出具體假說（例如高詳細回饋對頻率、深度分別是正向還是負向預測）。
假說 → 架構：資訊不足以判斷。
架構 → 分析：資訊不足以判斷 — 尤其「頻率」「深度」兩指標各自怎麼進統計模型（分開跑、還是合成一個依賴分數）還沒定案。
分析 → 結論：資訊不足以判斷。

## 檢查點 G：對抗式審查
1. **價值審查**：教這門課的教師、程式設計教育研究者可以用結果決定「回饋要給多詳細才不會養出AI依賴」，價值明確。
2. **理論解構**：關鍵假設是「鷹架撤除會逼出內化的自我調節」，但這個假設沒有考慮到生成式AI提供了一個幾乎零成本的替代鷹架。另外還有一個更隱蔽的競爭假設你目前沒處理——方向可能是反過來的：高詳細回饋反而「示範」了一種被動接受完整解答的模式，讓學生養成向AI要「完整修正後程式碼」（求助深度更高）的習慣，而不是降低依賴。這兩個方向都講得通，你需要在文獻回顧中先表態選哪一個，研究問題才能寫出明確的假說方向。
3. **方法論審計**：
   - 方法類型與問題型態相符：量化實驗設計配行為紀錄資料，方向正確。
   - 抽樣：兩班各約 40 人，再分高低各約 20 人，樣本量偏小，若要偵測中小效果量，檢定力可能不足，建議先做 power analysis 估計最小需要樣本數。
   - 隨機分派若在班級內進行，兩個班本身（不同教師、不同教學風格、可能不同進度）是一個 clustering 因素，目前沒有提到怎麼在分析中處理（例如納入班級作為共變項，或用 multilevel model），否則班級差異可能混淆回饋詳細程度的效果。
   - 測量工具：「求助深度」若靠人工判讀對話紀錄分類，需要明確的編碼架構與跨編碼者信度（inter-rater reliability）；目前沒提到這一步。
   - 操弄檢核（manipulation check）：需要確認兩組教師真的按「高／低詳細」的設計發送回饋，而不是無意間發出中間程度的回饋，稀釋了實驗操弄。
4. **可行性與備胎**：通過 — 一學期 80 人資料來源具體，且已有明確降級方案（退回相關性問卷研究）。
5. **具體建議**：
   - 把理論缺口的論證從「沒人測過」改寫成「Zimmerman 鷹架遞減假設依賴 X 前提，生成式AI的普及打破了這個前提」的完整版本。
   - 把研究問題句型從是非句改成效果／方向句型，並在文獻回顧先表態預期方向（或說明兩個競爭方向都成立、留給資料檢驗）。
   - 補齊「高／低詳細回饋」的具體操作定義，規劃 manipulation check。
   - 決定「頻率」「深度」兩指標是合成單一依賴分數還是分開分析，並補上「求助深度」的編碼架構與信度檢核計畫。
   - 若隨機分派落在班級內，分析設計要納入班級／教師作為控制變項，並先做 power analysis 確認每組 20 人是否足夠。
