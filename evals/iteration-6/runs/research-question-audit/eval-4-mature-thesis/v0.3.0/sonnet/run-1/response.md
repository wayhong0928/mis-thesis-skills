# 研究問題稽核報告

## 稽核對象
「探討教師回饋詳細程度對大學生於程式設計課程中使用生成式AI除錯行為的效果。研究問題：教師提供的除錯回饋詳細程度，是否會影響學生對生成式AI工具的除錯依賴程度？」（缺口主張：理論缺口——Zimmerman自我調節學習理論的鷹架遞減機制，尚未在生成式AI輔助除錯情境下被檢驗。依變數：除錯依賴程度，以AI工具使用頻率、求助深度兩指標量化。自變數：教師回饋詳細程度（高／低），兩班各約40人隨機分派，回饋透過線上作業系統個別發送。已與兩位教師談好合作，一學期約80人資料。降級方案：改為單一時間點問卷，僅探討相關而非因果。）

## 檢查點 A：研究缺口分類
判定：**不通過**
理由：使用者標為理論缺口，但論證方式其實是「某理論在情境A已驗證，情境B（生成式AI除錯）還沒人測過」——這正是情境缺口紅線要嚴格擋下的新穎性宣稱模式，只是包了一層理論構念的外衣。理論缺口的判準要求指名「理論的哪一個構念或路徑無法涵蓋觀察到的現象」，而不是「這個機制還沒被測過」。目前缺的兩欄是：(1) Zimmerman理論的鷹架遞減假設具體依賴什麼前提（例如：外部鷹架來源有限、會隨能力提升而自然淡出）；(2) 生成式AI除錯工具的哪個特性可能推翻這個前提（例如：AI求助是近乎零成本、無社會壓力、隨時可得的替代性外部資源，可能使鷹架不會隨能力提升而遞減，反而被AI取代而持續存在甚至增加）。把這兩欄寫清楚，才是站得住的理論缺口。

## 檢查點 D：壞題目長相比對
命中：
- **③ 變數沒有理論來源（疑慮）**：自變數「回饋詳細程度」有Zimmerman SRL理論支撐，但依變數「除錯依賴程度」本身目前只有操作型定義（頻率＋求助深度），沒有交代這個構念對應到哪個既有理論脈絡（例如cognitive offloading、automation bias、或AI reliance相關文獻）。建議補上依變數的理論根源，否則會被質疑是研究者自行定義的臨時構念。

其餘（①②⑤⑥）未命中：① 有明確依變數；② 只有一條研究問題、依變數雖有兩指標但同屬一個構念的兩個面向，戰線合理；⑤ 「教師回饋詳細程度」在傳統教學回饋文獻中已有大量研究，但「回饋詳細程度 × 生成式AI除錯依賴」的組合目前看來有一定新穎性，建議仍需查文獻確認近似研究是否已存在（例如AI over-reliance教育研究是否已處理過回饋介入變數），暫列為**不確定**；⑥ 有明確可否證的方向性假設空間，可否證。

## 檢查點 E：句型與常見錯誤
句型判定：不符合對應研究取向的量化句型 — 目前設計是實驗比較組間差異，應對應「組間差異」或「直接效果」句型，而非是非問句。
是非問句紅線：**不通過** — 「⋯是否會影響⋯」是典型可以一個字回答完的是非句，沒有交代效果方向或強度。建議改為：「相較於低詳細回饋，高詳細回饋對學生生成式AI除錯依賴程度（頻率、求助深度）的影響為何？」或「教師回饋詳細程度（高／低）對學生除錯依賴程度的組間差異效果為何？」
常見錯誤命中：第1條（是非問句寫法，同上）。其餘7條未命中。

## 檢查點 F：一致性檢查鏈
- 目的 → 問題：通過，研究目的已收斂成一個具體問題。
- 問題 → 假說：**資訊不足以判斷** — 使用者尚未提供方向性假說（例如高詳細回饋是否預期降低或提高依賴程度）。
- 假說 → 架構：**資訊不足以判斷** — 尚無研究架構圖或是否納入控制變數（如學生先備程式能力、班級/教師固定效果）的說明。
- 架構 → 分析：**資訊不足以判斷** — 尚未說明統計分析方法（如獨立樣本t檢定、ANCOVA、或以班級為隨機效果的多層次模型）。
- 分析 → 結論：**資訊不足以判斷** — 待上述環節補齊後才能判斷。

## 檢查點 G：對抗式審查
1. **價值審查**：程式設計課教師、教學設計者、教育科技決策者會在乎——答案可直接用來決定回饋設計策略（要不要投入成本寫詳細回饋）、以及是否需要對學生使用GenAI除錯訂出引導或限制政策。價值明確。
2. **理論解構**：Zimmerman鷹架遞減假設依賴「外部鷹架來源有限，能力提升後會自然淡出對外部協助的需求」這個前提。生成式AI提供近乎零成本、無社會壓力、隨時可得的替代性外部資源，可能使這個前提不成立——學生即使能力提升，仍可能因為AI太方便而持續依賴，鷹架不但不遞減反而被AI取代並延續。這正是檢查點A要求補齊的那兩欄內容，也是整個研究真正有價值的理論論證核心，值得優先寫清楚。
3. **方法論審計**：
   - 方法類型與問題型態相符：量化組間比較問題配隨機分派實驗，方法類型正確。
   - 抽樣是否撐得住宣稱：兩班各40人、班級內隨機分派高低組（每班20/20，共約40人/組），這個設計把「班級／教師風格」這個潛在混淆因子控制在班級內比較，設計合理。但要留意兩個風險：(a) 樣本量對於偵測中等以下效果量是否足夠，建議做power analysis 確認；(b) 同班內高低組學生可能互相討論回饋內容，造成實驗污染（treatment diffusion），需要在方法設計中加入防範機制（例如提醒學生不得討論回饋、或說明如何監控）。
   - 測量工具是否恰當：核心疑慮在依變數的量化方式——「求助深度」（只問錯誤訊息意思 vs. 要完整修正程式碼）需要對AI工具的對話紀錄做分類，若要達到可信的信效度，需要說明分類編碼方式（人工編碼？NLP自動分類？）與編碼者間信度，目前完全沒有交代，屬於重大缺口。
4. **可行性與備胎**：已有具體降級方案（單一時間點問卷、放棄因果推論），可行性風險已被部分處理。但降級方案把「行為紀錄」換成「問卷自陳」，等於連測量方法都整套換掉，建議先想清楚兩套操作化方式測的是不是同一個構念，避免正式研究與降級研究之間的結果無法互相對照。
5. **具體建議**：
   - 優先把理論缺口論證改寫為「Zimmerman哪個具體假設 + 被GenAI哪個特性動搖」的完整版本。
   - 把研究問題句型改為方向性效果句型，避免是非問句。
   - 確認AI工具使用紀錄的技術取得方案（是否有校方可控的中介介面），這是整個研究能不能執行的關鍵前提，建議列為最優先確認事項。
   - 為「除錯依賴程度」補上理論根源（如cognitive offloading、automation bias相關文獻）。
   - 做樣本量power分析，並在設計中加入防止班級內組間污染的具體做法。
   - 補齊方向性假說、研究架構（含控制變數）與統計分析方法，完成一致性檢查鏈。

總結：**可進行 / 需修正後再議 / 需重新收斂** → **需修正後再議**。題目已收斂到位、資料合作也談好了，架構基礎扎實，但理論缺口論證、依變數的資料取得方案、研究問題句型三處需要修正後才站得住。
