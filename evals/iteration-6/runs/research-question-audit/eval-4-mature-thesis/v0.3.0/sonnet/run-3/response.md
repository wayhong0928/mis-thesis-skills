# 研究問題稽核報告

## 稽核對象
「探討教師回饋詳細程度對大學生於程式設計課程中使用生成式AI除錯行為的效果」；研究問題：「教師提供的除錯回饋詳細程度，是否會影響學生對生成式AI工具的除錯依賴程度？」

## 檢查點 A：研究缺口分類
**判定：不通過（宣稱理論缺口，但論述方式其實命中情境缺口的紅線）**

理由：你的論述是「Zimmerman 理論主張外部回饋鷹架作用會隨能力提升遞減，但沒有文獻檢驗這個機制在『生成式AI輔助除錯』這個新情境下是否成立」。這句話的結構是「理論在別的情境驗證過，但還沒人在這個新情境（這裡是換成『新工具情境』而非地理/產業）做過」——這正是情境缺口的紅線不合格寫法，只是把「還沒人在台灣做過」換成「還沒人在生成式AI情境做過」，本質相同。

若要成立為理論缺口，你必須指出 Zimmerman 理論**哪一個構念或路徑**無法涵蓋觀察到的現象（例如：理論假設「外部鷹架消退＝內化自我調節能力上升」，但當外部鷹架換成一個「永遠即時、零成本、不會隨能力提升而自然撤除」的 AI 工具時，鷹架消退的機制本身可能不成立，因為學生不必等待能力提升，隨時可以召喚外部支持）。你目前只寫到「沒人測過」，沒有寫到「哪個機制可能失效、為什麼」。

若改走情境缺口，則需補齊兩欄：(1) 原理論依賴的哪一條假設（例如：假設除了教師回饋外，沒有其他隨時可得的外部支持來源）；(2) 被本情境的哪一個特性推翻（例如：生成式AI的出現，讓「零成本、即時、無上限」的外部支持首度存在，使得原本「鷹架隨能力遞減」的假設可能不再成立）。兩欄缺一即不通過。

3. 缺口分類明確：**不通過** — 見檢查點 A。

## 檢查點 E：句型與常見錯誤
句型判定：這是量化組間比較設計，理論上應套用「組間差異」或「直接效果」句型，但目前寫法不符。

**是非問句紅線：不通過**。「教師提供的除錯回饋詳細程度，是否會影響學生對生成式AI工具的除錯依賴程度？」是典型「X是否影響Y」句型，一個字就能回答完，沒有指出方向或強度。應改寫為例如：「接受高詳細度與低詳細度除錯回饋的學生，在生成式AI除錯依賴程度上的差異為何？」或「教師回饋詳細程度對學生除錯依賴程度的預測效果（方向與強度）為何？」

常見錯誤命中：
- 第1條（是非問句）：命中，見上。
- 第5條（變數缺乏可辨識定義）：不確定——「高詳細」與「低詳細」回饋目前沒有操作型定義（字數？是否含程式碼片段？是否指出錯誤位置與原因？），也沒有提到操弄檢核（manipulation check）確認學生真的感受到兩組的差異。

## 檢查點 F：一致性檢查鏈
- 目的 → 問題：通過（大致對應）。
- 問題 → 假說：**資訊不足以判斷** — 目前沒有方向性假說（依賴程度是預期上升還是下降？兩派解讀都合理：低詳細回饋逼學生更依賴AI補洞，或高詳細回饋讓學生更熟悉「有回饋」的求助模式而更依賴——方向不明）。
- 假說 → 架構：**資訊不足以判斷** — 未提供研究架構圖，也未知是否有控制變數（如學生先備程式能力，這在自我調節學習研究中通常是關鍵調節/控制變數）。
- 架構 → 分析：**資訊不足以判斷** — 未說明統計分析方法。
- 分析 → 結論：**資訊不足以判斷**。

## 檢查點 G：對抗式審查
1. **價值審查**：授課教師與課程設計者可用此結果決定回饋撰寫政策（例如是否該限制詳細回饋以避免養成AI依賴）；對象與用途大致明確，但建議在論文中更具體點名（例如：CS1教學助理訓練規範、線上作業系統的自動回饋模板設計）。

2. **理論解構**：Zimmerman 模型隱含一個關鍵假設——「除了教師回饋外，沒有其他隨時可得、零成本的外部支持來源」。生成式AI工具打破了這個假設：它讓學生可以繞過教師回饋，直接召喚一個不受能力高低限制的外部鷹架。如果這個假設不成立，那麼「回饋詳細程度」可能根本不是決定依賴程度的主要變數（真正的驅動力可能是「AI工具的可近用性/便利性」，回饋詳細與否只是次要因素）。這是整個研究問題成立與否的關鍵理論假設，建議在文獻回顧中正面處理。

3. **方法論審計**：
   - 方法類型與問題型態相符（組間比較，適合量化實驗設計）。
   - 抽樣：每組約40人（2班×2條件），樣本量對於偵測中小效果量的t檢定/迴歸來說偏緊，建議做事前檢定力分析。更關鍵的風險是**班級內隨機分派的污染（SUTVA違反）**——同班學生若接受不同詳細程度的回饋，彼此討論、互相比對回饋內容或求助內容，會稀釋處理效果；需要說明如何防止污染（例如禁止討論回饋內容的規範、或分析時用多層次模型處理班級巢套結構）。
   - 測量工具：目前對「除錯依賴程度」的操作化（使用紀錄量化）尚未有驗證過的既有量表可循，且資料存取方式未定（見D④），是本設計最大的方法論缺口。

4. **可行性與備胎**：一學期、80人的資料規模基本可行；但你目前只針對「隨機分派做不成」設計了降級方案（改問卷測感受到的回饋詳細程度與除錯依賴程度的相關），沒有針對「AI使用紀錄拿不到」設計降級方案——如果拿不到真實使用紀錄，即使隨機分派做成了，DV也測不到。建議也準備一個「用自陳量表測量使用頻率與求助深度」的備案，獨立於隨機分派是否成功。

5. **具體建議**：
   - 把研究缺口從「理論缺口」誠實地重新定位——若堅持理論缺口，需具體指出 Zimmerman 理論的哪個構念/路徑可能失效並說明機制；若改走情境缺口，補齊「原假設」與「被推翻的情境特性」兩欄。
   - 把研究問題從是非句改寫為方向性/組間差異句型。
   - 補上「高/低詳細回饋」的具體操作型定義，並規劃操弄檢核。
   - 在提案給合作老師之前，先確認AI使用紀錄的具體技術取得方案（是否透過課程指定的中介介面記錄？學生個人帳號的ChatGPT/Copilot紀錄如何合法取得？IRB/知情同意如何處理對話內容隱私？），這是目前最可能讓整個設計卡住的環節，建議優先處理。
   - 補上假說方向、研究架構圖與統計分析方法（例如獨立樣本 t 檢定/ANCOVA控制先備程式能力，或多層次模型處理班級巢套）。
   - 處理班級內隨機分派的擴散污染風險。
